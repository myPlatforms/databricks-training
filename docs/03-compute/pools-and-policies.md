# 인스턴스 풀과 컴퓨트 정책

> 기준일: 2026-10-28 · 근거: 공식 문서 · 수준: 300

클래식 컴퓨트를 운영 규모로 쓰려면 두 가지 기능이 필요합니다. 인스턴스 풀(Instance pool)은 클러스터 시작 시간을 줄이고, 컴퓨트 정책(Compute policy)은 사용자가 만들 수 있는 컴퓨트의 설정 범위를 제한합니다. 이 페이지는 두 기능의 동작과 과금 규칙, 권한, 제한 범위를 다룹니다. 두 기능은 서버리스 컴퓨트에서 지원하지 않습니다.

## 1. 왜 필요한가

### 1.1 풀이 필요한 이유

클러스터를 만들 때마다 클라우드 인스턴스를 새로 할당하면 시작에 시간이 걸립니다. 자주 만들고 지우는 워크로드에서는 이 시간이 누적됩니다. 풀은 미리 준비된 유휴 인스턴스를 두고, 클러스터가 그 인스턴스를 가져다 쓰게 합니다.

### 1.2 정책이 필요한 이유

클러스터 설정을 사용자 자유에 맡기면 다음 문제가 생깁니다.

| 문제 | 정책으로 막는 방법 |
|---|---|
| 허용되지 않은 큰 노드 유형 선택 | 노드 유형을 제한 |
| 클러스터당 비용 상한 초과 | 클러스터당 최대 비용을 제한 |
| 특정 라이브러리 설치 강제 | 컴퓨트 범위 라이브러리 설치를 강제 |
| 설정 표준 불일치 | 사전 정의된 설정만 허용 |

문서는 정책을 "a tool workspace admins can use to limit a user or group's compute creation permissions"로 설명합니다.

## 2. 어떻게 동작하는가

### 2.1 인스턴스 풀

풀은 유휴 상태로 대기하는 인스턴스 집합입니다. 풀에서 만든 클러스터 노드는 유휴 인스턴스에서 생겨 더 빨리 시작하고 오토스케일링도 빨라집니다. 풀에 유휴 인스턴스가 없으면 풀이 클라우드 제공자에게서 새 인스턴스를 할당합니다.

공식 문서는 서버리스 컴퓨트가 지원하는 워크로드라면 풀보다 서버리스를 먼저 쓰라고 권장합니다.

#### 과금 규칙

이 부분은 문서의 표현을 그대로 옮깁니다.

| 항목 | 문서 원문 |
|---|---|
| 유휴 인스턴스의 DBU | "Databricks does not charge DBUs while instances are idle in the pool." |
| 유휴 인스턴스의 클라우드 요금 | "Instance provider billing does apply." |

즉, 풀에 대기 중인 인스턴스는 DBU는 청구되지 않지만 클라우드 제공자의 인스턴스 요금은 계속 청구됩니다. 풀의 크기를 키울수록 유휴 상태의 클라우드 비용이 늘어납니다.

#### 권한과 생성

| 항목 | 문서 내용 |
|---|---|
| 풀 생성 | **Allow pool creation** 권한이 필요합니다. 기본으로는 워크스페이스 관리자만 갖고, 관리자가 사용자·서비스 프린시펄·그룹에 부여할 수 있습니다 |
| 풀 권한 설정 | CAN MANAGE 권한이 필요합니다 |
| 풀 권한 수준 | NO PERMISSIONS, CAN ATTACH TO, CAN MANAGE |

#### 클러스터에 풀 연결

UI에서는 클러스터 생성 화면의 **Driver Type** 이나 **Worker Type** 드롭다운에서 풀을 고릅니다. API에서는 드라이버에 `driver_instance_pool_id`, 워커에 `instance_pool_id`를 씁니다.

```python
# 클러스터 명세 예: 드라이버와 워커를 풀에서 가져오도록 지정합니다.
# 풀 ID는 워크스페이스에서 생성한 풀의 값을 넣으십시오.
cluster_spec = {
    "cluster_name": "pooled-etl-example",
    "spark_version": "<DBR_VERSION>",
    "driver_instance_pool_id": "<DRIVER_POOL_ID>",
    "instance_pool_id": "<WORKER_POOL_ID>",
    "autoscale": {"min_workers": 2, "max_workers": 8},
}
```

> **주의** 드라이버에 스팟 인스턴스를 쓰는 풀을 쓰지 마십시오. 문서가 드라이버에 대해 명시적으로 금지합니다.

오토스케일링과 풀을 함께 쓸 때는 요청 크기를 맞춰야 합니다. 문서 기준으로 요청한 최소 크기는 풀의 최소 유휴 인스턴스 수 이하이고, 최대 크기는 풀의 최대 용량 이하여야 합니다.

#### 풀의 제한

- **풀 삭제**: 유휴 인스턴스를 종료하고 설정을 지우며, 되돌릴 수 없습니다.
- **실행 중인 클러스터**: 삭제된 풀에 붙어 있던 실행 중 클러스터는 계속 돌지만, 리사이즈나 확장 때 인스턴스를 새로 받지 못합니다.
- **종료된 클러스터**: 삭제된 풀에 붙어 있던 종료 상태 클러스터는 다시 시작하지 못합니다.
- **태그**: 풀에서 만든 컴퓨트에 붙인 커스텀 태그는 DBU 사용 보고서에만 적용되고, 클라우드 리소스에는 적용되지 않는다고 문서가 설명합니다.

### 2.2 컴퓨트 정책

정책은 사용자가 컴퓨트를 만들 때 고를 수 있는 설정 범위를 정합니다. 문서 기준 동작은 다음과 같습니다.

| 항목 | 문서 내용 |
|---|---|
| 권한이 없는 사용자 | "Unrestricted cluster creation" 권한이 없으면 부여받은 정책으로만 컴퓨트를 만들 수 있습니다 |
| 기본 정책 | 모든 사용자가 **Personal Compute** 정책을 기본으로 갖습니다 |
| 정책 접근 | 기본적으로 워크스페이스 관리자가 모든 정책에 권한을 갖고, 비관리자는 정책 권한을 부여받아야 접근합니다 |
| 컴퓨트 추가 | 정책에 컴퓨트를 추가하려면 워크스페이스 관리자여야 합니다 |
| 정책 정의 | JSON으로 편집할 수 있습니다. 정책 패밀리(Policy family)는 Databricks가 제공하는 사전 정의 템플릿입니다 |

정책이 제한할 수 있는 예는 다음과 같습니다. 문서가 제시한 목적입니다.

- 정해진 설정으로만 클러스터를 만들도록 제한
- 클러스터당 최대 비용 제한
- 클러스터 범위 라이브러리 설치 강제

정책 JSON의 속성 구문(고정, 제한, 허용 목록, 숨김 등 규칙 유형)은 이 장에서 원문으로 확인하지 못했습니다. 정책 작성 시에는 정책 레퍼런스 문서를 따로 확인하십시오. 정책 페이지의 **Compute policy reference** 링크가 그 문서를 가리킵니다.

> **참고** 정책 페이지는 정책 준수 상태 라벨을 설명합니다. Auto-fixable, Manual edit required, Enforce scheduled, Enforce scheduled stale, Could not determine, 그리고 올-퍼포즈 컴퓨트 상세 화면의 "Out of compliance"입니다. 이 라벨은 기존 클러스터가 정책과 맞는지 보여 주는 용도입니다.

### 2.3 서버리스와의 관계

서버리스 컴퓨트는 컴퓨트 정책, 인스턴스 풀, 컴퓨트 범위 init 스크립트를 지원하지 않습니다([서버리스 제약](serverless-limitations.md) 참고). 서버리스의 사용 제어는 **서버리스 사용 정책(Serverless usage policy)** 이 맡습니다. 이 기능은 문서에 Public Preview로 표기되어 있습니다.

## 3. 어떻게 쓰는가

정책을 적용하는 일반 순서는 다음과 같습니다.

1. 관리자가 정책을 만들고 JSON 정의에 허용 설정을 씁니다.
2. 정책에 사용자 또는 그룹의 권한을 부여합니다.
3. 필요하면 풀을 만들고 정책 권한과 풀 권한(CAN ATTACH TO)을 나눠 줍니다.
4. 사용자는 허용된 정책 목록에서만 클러스터를 만듭니다.

풀 권한을 CLI로 다루는 세부 명령은 이 장에서 확인하지 못했습니다. 풀 생성과 권한은 워크스페이스 UI나 공식 API 레퍼런스에서 확인하십시오.

## 4. 트레이드오프

| 기능 | 장점 | 비용과 한계 |
|---|---|---|
| 풀 | 클러스터 시작 시간 단축 | 유휴 인스턴스의 클라우드 요금이 계속 나갑니다 |
| 풀 | 오토스케일링 확장 속도 개선 | 풀 삭제는 되돌릴 수 없습니다 |
| 정책 | 설정 표준화와 비용 상한 | 정책 JSON을 잘못 쓰면 사용자가 클러스터를 못 만듭니다 |
| 정책 | 권한 기반 통제 | 정책 권한 관리가 추가됩니다 |
| 서버리스 대체 | 풀과 정책 관리가 필요 없습니다 | 서버리스가 지원하는 워크로드에서만 가능합니다 |

## 5. 주의사항

- **풀 크기를 보수적으로 잡으십시오.** 유휴 인스턴스는 DBU 없이 클라우드 요금이 나갑니다. 쓰지 않는 풀은 유휴 비용만 쌓입니다.
- **드라이버에 스팟 인스턴스 풀을 쓰지 마십시오.** 문서의 명시 금지 사항입니다.
- **정책으로 기본 클러스터 경로를 정하십시오.** 권한이 없는 사용자는 정책 없이 클러스터를 만들 수 없습니다. 개인 실습용은 Personal Compute 정책을 씁니다.
- **풀을 지우기 전에 의존 클러스터를 확인하십시오.** 삭제된 풀에 붙은 종료 상태 클러스터는 재시작하지 못합니다.
- **정책 준수 라벨을 주기적으로 보십시오.** Out of compliance 상태 클러스터는 정책 변경 후 맞춰야 합니다.
