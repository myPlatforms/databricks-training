# 예약 작업 (Scheduled tasks)

> 기준일: 2026-10-28 · 근거: 공식 문서

## 왜 필요한가

반복되는 점검은 사람이 기억해서 실행하기 어렵습니다. 매일 아침 전일 데이터를 확인하거나, 주간 지표를 요약하거나, 특정 테이블의 이상치를 살피는 일이 여기에 해당합니다. 노트북을 열어 같은 프롬프트를 매번 붙여 넣으면 시간이 들고, 실행 결과도 흩어집니다.

예약 작업은 **Genie Code 프롬프트를 정해진 시각에 자동 실행** 하는 기능입니다. 실행 한 번이 하나의 Genie Code 세션이며, 그 결과가 새 채팅으로 남습니다.

> **참고** 문서는 이 기능이 **대화형 채팅** 을 다루며, Lakeflow Job 안에서 Genie Code를 실행하는 것은 별도 기능이라고 구분합니다. Job 안 실행은 [Lakeflow Jobs의 Genie Code 태스크](lakeflow-jobs-task.md)를 참고하십시오.

## 어떻게 동작하는가

### 생성 방법

| 방법 | 절차 |
|------|------|
| 채팅으로 요청 | 자연어로 요청합니다. 예: "매일 오전 8시에 어제 주문 테이블을 점검해 줘." Genie Code가 실행 시각 같은 정보를 되물을 수 있습니다. |
| 제안된 작업에서 시작 | 전체 화면 Genie Code에서 **Schedules** 아이콘(달력과 시계)을 눌러 예약 작업 패널을 엽니다. 제안된 작업을 고릅니다. 패널 케밥 메뉴에서도 열 수 있습니다. |
| 수동 생성 | **Scheduled tasks** 패널에서 **Create** 드롭다운 → **Create manually** → 항목 입력 → **Create** |

### 설정 항목

| 필드 | 설명 |
|------|------|
| Title | 작업 이름 |
| Prompt | 실행할 Genie Code 프롬프트 |
| Schedule | 실행 주기 |
| Timezone | 시간대 |

문서는 실행 사용자 지정 필드, 알림 설정, 출력 대상 설정을 명시하지 않습니다. 결과는 실행마다 생성되는 채팅으로 남는다고만 설명합니다.

### 실행 방식

- 실행은 대화형 세션과 같은 기능으로 돌아갑니다.
- 실행마다 자기 채팅이 생기며, 그 채팅을 검토하거나 이어서 작업할 수 있습니다.
- 실행 주체의 권한은 **작업 생성자의 권한** 을 씁니다. 문서는 "Runs use the permissions of the task's creator, governed by Unity Catalog permissions."라고 설명합니다.
- **자동 승인은 항상 켜져 있으며 끌 수 없습니다.** AI 분류기가 각 도구 동작을 프롬프트와 대조해 위험한 동작을 막습니다.

### 관리

| 동작 | 방법 |
|------|------|
| 목록 확인 | Scheduled tasks 패널에서 작업, 일정, 다음 실행 시각을 봅니다. |
| 상세 보기 | 상태, 일정, 프롬프트, **Run history** |
| 즉시 실행 | **Run now** |
| 일시 정지 | 작업을 끕니다 (Turning a task off). |
| 수정 | **Edit** 에서 Title, Prompt, Schedule, Timezone을 바꾼 뒤 **Save** |
| 삭제 | 케밥 메뉴 → **Delete** → 확인 |

## 어떻게 쓰는가

예를 들어 아래와 같은 프롬프트를 예약할 수 있습니다. 문서가 제시한 예시가 아니라 형태를 보여 주기 위한 예시입니다.

| 필드 | 값 (예시) |
|------|-----------|
| Title | 일간 주문 데이터 점검 |
| Prompt | `sales.orders` 테이블에서 어제 날짜 행 수를 집계하고, 최근 7일 평균과 비교해 30% 이상 차이가 나면 차이 원인을 요약해 줘. 테이블은 수정하지 마. |
| Schedule | 매일 오전 8시 |
| Timezone | 팀 기준 시간대 |

프롬프트에는 다음을 명시하는 것이 좋습니다.

- 대상 테이블의 완전한 이름
- 쓰기를 허용하는지 여부 (예: "수정하지 마")
- 결과 형식 (표 또는 요약 문단)

> **주의** 자동 승인이 항상 켜져 있으므로, 프롬프트에 쓰기 동작을 암묵적으로 포함하지 않습니다. 실행이 위험한 작업은 예약 작업 대신 승인을 거치는 대화형 세션이나 권한이 좁은 실행 주체에서 처리합니다.

## 트레이드오프

| 항목 | 내용 |
|------|------|
| 실행 결과 | 실행마다 새 채팅으로 남아 검토와 이어 작업이 쉽습니다. |
| 공유 | 작업 자체는 다른 사용자와 공유할 수 없습니다. 실행으로 생긴 채팅은 공유할 수 있습니다. |
| 사용량 | Genie 사용량에 포함됩니다. |
| 한도 도달 시 | 한도에 도달해도 실행은 시작되며, 대화형 세션과 같은 방식으로 실패합니다. |
| 자동 승인 | 항상 켜져 있어 끌 수 없습니다. 실행 전에 동작을 검토할 수 없습니다. |
| 권한 변경 | 연결된 MCP 권한이 바뀌면 사용자가 다시 인증할 때까지 실패합니다. |

### 예약 작업이 맞지 않는 경우

- 실행 결과를 다음 단계의 입력으로 넘겨야 할 때: Job 안에서 상위·하위 태스크 값으로 연결하는 편이 낫습니다. [Lakeflow Jobs의 Genie Code 태스크](lakeflow-jobs-task.md)를 보십시오.
- 쓰기 동작이 포함될 때: 자동 승인이 꺼지지 않으므로, 쓰기는 결정적인 코드 태스크나 승인 가능한 대화형 세션으로 분리합니다.
- 여러 사람이 같은 작업을 관리할 때: 작업 공유가 안 되므로, 생성자 퇴사나 권한 변경에 대비한 운영 절차가 필요합니다.

## 주의사항

- **상태 라벨**: 릴리즈 노트 2026-09-01에 "Genie Code scheduled tasks are now generally available"이 있습니다. 이 페이지 자체에는 라벨이 없습니다.
- **Compliance 보안 프로필 워크스페이스**: 릴리즈 노트 2026-10-05에 따르면 해당 프로필이 켜진 워크스페이스에서 예약 작업이 기본으로 제공됩니다.
- **작업 생성자 권한**: 생성자의 Unity Catalog 권한을 씁니다. 생성자가 바뀌거나 권한이 회수되면 작업이 실패할 수 있습니다.
- **클라우드 차이**: 이 페이지는 AWS 기준이며, 클라우드별 차이는 문서에 나오지 않습니다. 다른 클라우드 문서는 이 장에서 확인하지 않았습니다.
