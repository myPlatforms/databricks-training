# 예약 작업 (Scheduled tasks)

> 기준일: 2026-10-29 · 근거: 공식 문서 · 수준: 200

## 왜 필요한가

반복되는 점검은 사람이 기억해서 실행하기 어렵습니다. 매일 아침 전일 데이터를 확인하거나, 주간 지표를 요약하거나, 특정 테이블의 이상치를 살피는 일이 여기에 해당합니다. 노트북을 열어 같은 프롬프트를 매번 붙여 넣으면 시간이 들고, 실행 결과도 흩어집니다.

예약 작업은 **Genie Code 프롬프트를 정해진 시각에 자동 실행** 하는 기능입니다. 실행 한 번이 하나의 Genie Code 세션이며, 그 결과가 새 채팅으로 남습니다.

> **참고** 이 기능은 **대화형 채팅** 을 반복 실행하는 것입니다. Lakeflow Job 안에서 Genie Code를 한 태스크로 실행하는 것은 별도 기능입니다. 둘의 선택 기준은 아래 "예약 작업과 Lakeflow Jobs 태스크" 절을 보십시오. Job 안 실행의 자세한 내용은 [Lakeflow Jobs의 Genie Code 태스크](lakeflow-jobs-task.md)에서 다룹니다.

## 어떻게 동작하는가

### 생성 방법

문서가 설명하는 생성 방법은 세 가지입니다.

| 방법 | 절차 |
|------|------|
| 채팅으로 요청 | 자연어로 요청합니다. 예: "매일 오전 8시에 어제 주문 테이블을 점검해 줘." Genie Code가 실행 시각 같은 정보를 되물을 수 있습니다. |
| 제안된 작업에서 시작 | 전체 화면 Genie Code에서 **Schedules** 아이콘(달력과 시계)을 눌러 예약 작업 패널을 엽니다. 제안된 작업을 누르면 그 프롬프트가 Genie Code로 전달됩니다. 사이드 패널의 케밥 메뉴에서도 패널을 열 수 있습니다. |
| 수동 생성 | **Scheduled tasks** 패널에서 **Create** 드롭다운 → **Create manually** → 항목 입력 → **Create** |

문서에는 이 세 가지 외의 명령줄·API 진입점이 나오지 않습니다.

### 설정 항목

| 필드 | 설명 |
|------|------|
| Title | 작업 이름 |
| Prompt | 실행할 Genie Code 프롬프트 |
| Schedule | 실행 주기 |
| Timezone | 시간대 |

문서는 **Schedule** 값의 형식(cron 표현식 등)과 선택지 목록을 설명하지 않습니다. 실행 사용자 지정 필드, 알림 설정, 출력 대상 설정도 명시하지 않습니다. 결과는 실행마다 생성되는 채팅으로 남는다고만 설명합니다.

### 실행 방식

- 실행은 대화형 세션과 같은 기능으로 돌아갑니다.
- 실행마다 자기 채팅이 생기며, 그 채팅을 검토하거나 이어서 작업할 수 있습니다.
- 실행 주체의 권한은 **작업 생성자의 권한** 을 씁니다. 문서는 "Runs use the permissions of the user who created the task, governed by Unity Catalog permissions."라고 설명합니다.
- **자동 승인은 항상 켜져 있으며 끌 수 없습니다.** AI 분류기가 각 도구 동작을 프롬프트와 대조해 위험한 동작을 막습니다. 실행 전에 사람이 동작을 승인하는 단계는 없습니다.

### 관리

| 동작 | 방법 |
|------|------|
| 목록 확인 | Scheduled tasks 패널에서 작업, 일정, 다음 실행 시각을 봅니다. |
| 상세 보기 | 상태, 일정, 프롬프트, **Run history** |
| 즉시 실행 | 작업 상세의 재생 아이콘 **Run now** |
| 일시 정지 | 작업을 끕니다 (Turning a task off). 문서는 이를 별도의 재개 동작으로 설명하지 않습니다. |
| 수정 | **Edit** 에서 Title, Prompt, Schedule, Timezone을 바꾼 뒤 **Save** |
| 삭제 | 케밥 메뉴 → **Delete** → 한 번 더 **Delete** 로 확인 |

### 실행 기록

**Run history** 에서 실행을 고르면 그 실행이 Genie Code 채팅으로 열립니다. 그 채팅에서 결과를 검토하거나 대화를 이어 갈 수 있습니다. 실행 채팅은 공유할 수 있습니다. 작업 자체는 공유할 수 없습니다(아래 트레이드오프).

## 어떻게 쓰는가

예를 들어 아래와 같은 프롬프트를 예약할 수 있습니다. 문서가 제시한 예시가 아니라 형태를 보여 주기 위한 예시입니다.

| 필드 | 값 (예시) |
|------|-----------|
| Title | 일간 주문 데이터 점검 |
| Prompt | `sales.orders` 테이블에서 어제 날짜 행 수를 집계하고, 최근 7일 평균과 비교해 30% 이상 차이가 나면 차이 원인을 요약해 줘. 테이블은 수정하지 마. |
| Schedule | 매일 오전 8시 |
| Timezone | 팀 기준 시간대 |

프롬프트에는 다음을 명시하는 것이 좋습니다.

- 대상 테이블의 완전한 이름 (`카탈로그.스키마.테이블`)
- 쓰기를 허용하는지 여부 (예: "수정하지 마")
- 결과 형식 (표 또는 요약 문단)
- 차이가 났을 때 할 일과 하지 않을 일 (예: 원인 요약만, 재처리 금지)

> **주의** 자동 승인이 항상 켜져 있으므로, 프롬프트에 쓰기 동작을 암묵적으로 포함하지 않습니다. 실행이 위험한 작업은 예약 작업 대신 승인을 거치는 대화형 세션이나 권한이 좁은 실행 주체에서 처리합니다.

## 트레이드오프

| 항목 | 내용 |
|------|------|
| 실행 결과 | 실행마다 새 채팅으로 남아 검토와 이어 작업이 쉽습니다. |
| 공유 | 작업 자체는 다른 사용자와 공유할 수 없습니다. 실행으로 생긴 채팅은 공유할 수 있습니다. |
| 사용량 | Genie 사용량에 포함됩니다. |
| 한도 도달 시 | 한도에 도달해도 실행은 시작되며, 대화형 세션과 같은 방식으로 실패합니다. |
| 자동 승인 | 항상 켜져 있어 끌 수 없습니다. 실행 전에 동작을 검토할 수 없습니다. |
| 권한 변경 | 연결된 MCP 권한이 바뀌면 사용자가 다시 인증할 때까지 실패합니다. |

### 예약 작업과 Lakeflow Jobs 태스크

두 기능은 모두 Genie Code를 자동으로 실행하고, 두 기능 모두 자동 승인을 끌 수 없습니다. 선택은 실행 단위와 후속 처리가 필요한지에 따릅니다.

| 항목 | 예약 작업 (Scheduled tasks) | Lakeflow Jobs의 Genie Code 태스크 |
|------|------------------------------|-----------------------------------|
| 실행 단위 | 반복 일정에 따른 하나의 Genie Code 세션 | Job 실행 안의 한 태스크 |
| 입력 | Title, Prompt, Schedule, Timezone | Prompt와 Job 파라미터, 상위 태스크 값 |
| 실행 결과 | 실행마다 새 채팅 | Run output의 대화 링크와 응답, 다음 태스크가 참조하는 출력 |
| 다음 단계 연결 | 문서상 없음 | `{{tasks.<task_name>.output.response}}`, 조건 분기, 다른 태스크 파라미터 |
| 재시도·알림 | 문서에 명시 없음 | Advanced 설정에서 재시도, 임계값, 알림 설정 |
| 실행 주체 | 작업 생성자 권한 (Unity Catalog 권한 적용) | 문서에 run-as 명시 없음 |
| 공유 | 작업 공유 불가. 실행 채팅은 공유 가능 | 문서에 명시 없음 |
| 상태 | 릴리즈 노트 2026-09-01 GA. 페이지 라벨 없음 | 릴리즈 노트 2026-10-21 GA. 2026-08-27에는 Beta. 페이지 라벨 없음 |

선택 기준은 다음과 같습니다.

- **정해진 시각에 사람이 결과를 읽으면** 예약 작업이 맞습니다. 실행마다 채팅이 남아 검토하기 좋습니다.
- **결과를 다음 태스크로 넘기거나 Job의 실패·재시도 체계 안에 두어야 하면** Lakeflow Jobs의 Genie Code 태스크가 맞습니다. 상위 태스크 값과 응답 참조를 쓸 수 있습니다.
- **쓰기 동작이 필요하면** 둘 다 맞지 않습니다. 쓰기는 결정적인 코드 태스크로 분리합니다.

## 예약 작업이 맞지 않는 경우

- 실행 결과를 다음 단계의 입력으로 넘겨야 할 때: Job 안에서 상위·하위 태스크 값으로 연결하는 편이 낫습니다. [Lakeflow Jobs의 Genie Code 태스크](lakeflow-jobs-task.md)를 보십시오.
- 쓰기 동작이 포함될 때: 자동 승인이 꺼지지 않으므로, 쓰기는 결정적인 코드 태스크나 승인 가능한 대화형 세션으로 분리합니다.
- 여러 사람이 같은 작업을 관리할 때: 작업 공유가 안 되므로, 생성자 퇴사나 권한 변경에 대비한 운영 절차가 필요합니다.

## 주의사항

- **작업 생성자 권한**: 생성자의 Unity Catalog 권한을 씁니다. 생성자가 바뀌거나 권한이 회수되면 작업이 실패할 수 있습니다. 생성자 퇴사 전에 작업을 점검하는 절차를 두십시오.
- **자동 승인 가정**: 실행 중 사람이 개입하지 않습니다. 프롬프트가 결과를 보장한다고 가정하지 말고, 실행 채팅을 주기적으로 검토하십시오.
- **사용량 한도에 걸리면 실행이 실패합니다**: 문서에 따르면 한도에 도달해도 실행은 시작되며, 대화형 세션과 같은 방식으로 실패합니다. Run history에서 실패 여부를 확인하십시오.
- **상태 라벨**: 릴리즈 노트 2026-09-01에 "Genie Code scheduled tasks are now generally available"이 있습니다. 이 페이지 자체에는 라벨이 없습니다.
- **Compliance 보안 프로필 워크스페이스**: 릴리즈 노트 2026-10-05에 따르면 해당 프로필이 켜진 워크스페이스에서 예약 작업이 기본으로 제공됩니다.
- **클라우드 차이**: 이 페이지는 AWS 기준이며, 클라우드별 차이는 문서에 나오지 않습니다. 다른 클라우드 문서는 이 장에서 확인하지 않았습니다.
