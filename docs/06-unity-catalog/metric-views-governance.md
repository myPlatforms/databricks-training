# 메트릭 뷰의 거버넌스

> 기준일: 2026-10-28 · 근거: 공식 문서

> **참고** 이 페이지는 메트릭 뷰의 **정의 방식과 거버넌스 측면** 만 다룹니다. 대시보드, Genie 공간, 에이전트에서 메트릭 뷰를 쓰는 방법은 07장 AI/BI 범위입니다.

## 한눈에 보기

**메트릭 뷰**(Metric view)는 비즈니스 지표의 정의를 한곳에 두는 UC 객체입니다. 측정값(measure)과 그것을 묶는 기준 필드(dimension)를 분리해서 정의하고, 사용자는 어떤 필드로든 묶고 걸러서 지표를 조회할 수 있습니다. 공식 문서는 메트릭 뷰를 "Unity Catalog의 시맨틱스를 구현하는 핵심 객체"로 설명합니다.

UC 객체 분류에서 메트릭 뷰는 **뷰(View)의 한 종류** 입니다. 공식 문서의 securable 객체 표는 뷰를 "구체화된 뷰와 메트릭 뷰"의 상위 유형으로 나눕니다. 따라서 권한, 소유권, 공유 같은 거버넌스 규칙은 뷰의 규칙을 따르되, 메트릭 뷰에 특화된 규칙(예: 공유 범위)은 별도로 확인해야 합니다.

| 항목 | 일반 뷰 | 메트릭 뷰 |
|---|---|---|
| 집계 방식 | 생성 시 `GROUP BY`와 집계가 고정 | 쿼리 시점에 사용자가 고른 필드로 집계 |
| 정의 단위 | 저장된 SQL 쿼리 | 측정값과 필드의 의미 정의 |
| 쿼리 엔진 | 저장된 쿼리를 실행 | 엔진이 쿼리를 생성해 계산 |

공식 문서는 일반 뷰와의 차이를 이렇게 설명합니다. 일반 뷰는 집계와 묶음 기준을 생성 시점에 고정하지만, 메트릭 뷰는 측정값을 한 번 정의하면 사용자가 어떤 필드로든 묶을 수 있다는 것입니다. 예를 들어 "매출 합계 ÷ 고유 고객 수" 같은 지표를 한 번 정의하면, 날짜·지역·제품 등 임의의 필드로 묶어 조회하는 방식입니다.

## 1. 왜 필요한가

### 이전 방식의 한계

- 같은 지표(예: 매출)가 노트북, 대시보드, BI 도구마다 다른 SQL로 다시 정의되어 값이 엇갈립니다.
- 지표 정의가 여러 뷰에 흩어지면 정의를 바꿀 때 모든 뷰를 고쳐야 합니다.
- 일반 뷰로 모든 묶음 조합을 만들면 뷰가 수없이 늘어납니다.

메트릭 뷰는 지표 정의를 **UC 객체 하나** 에 모읍니다. 정의가 한 곳에 있으니 권한과 소유권을 그 객체에 부여하고, 정의 변경도 한 번만 하면 됩니다.

## 2. 어떻게 동작하는가

### 메트릭 뷰의 구성 요소

공식 문서가 설명하는 모델링 요소는 다음과 같습니다.

| 요소 | 설명 |
|---|---|
| 원천(Source) | 지표를 계산할 테이블이나 뷰. 스타 스키마와 스노플레이크 스키마를 다중 수준 조인으로 구성할 수 있습니다. |
| 필드(Field, dimension) | 묶거나 필터링할 기준 열 |
| 측정값(Measure) | 집계 지표 정의 |
| 필터(Filter) | 정의에 붙는 조건 |
| 윈도 측정값(Window measure) | 이동 평균, 전년 대비 변화, 누적 합계 같은 기간 계산 |

공식 문서에 따르면 메트릭 뷰는 다음 방식으로 만들 수 있습니다.

- SQL DDL로 정의합니다.
- 카탈로그 탐색기 UI에서 만들며, UI에는 YAML 검증이 포함되어 있습니다. YAML 문법 참고 페이지는 공식 문서에 별도로 있습니다.

### 메트릭 뷰의 부가 기능

| 기능 | 설명 | 상태 |
|---|---|---|
| 매개변수(Parameters) | 쿼리 시점에 값을 바인딩해 하나의 메트릭 뷰에서 여러 쿼리 변형을 만듭니다. | 문서에 상태 라벨 없음 |
| 구체화(Materialization) | 집계를 미리 계산하고 점진적으로 갱신합니다. 쿼리 엔진이 적절할 때 구체화된 뷰로 쿼리를 바꿔 실행할 수 있습니다. | 문서에 상태 라벨 없음 |
| 에이전트 메타데이터 | 동의어, 표시 이름, 서식 규칙을 붙여 AI 에이전트가 필드를 이해하게 합니다. | 문서에 상태 라벨 없음 |
| 윈도 측정값 | 이동 평균, 기간 대비 변화, 누적 합계 | GA (2026-10-06 릴리즈 노트) |
| 숫자 인덱스 열 기반 윈도 측정값 | 숫자 타입 인덱스 열 위의 윈도 측정값 | 릴리즈 노트에 상태 라벨 없음 (2026-09-14) |

## 3. 어떻게 쓰는가

### SQL로 메트릭 뷰 정의하기

공식 문서는 메트릭 뷰를 SQL DDL로 만들 수 있다고 설명하지만, 이 장에서 확인한 페이지에는 `CREATE VIEW ... WITH METRICS` 같은 구체 문법과 YAML 본문 예제가 없었습니다. 따라서 이 장에서는 문법을 쓰지 않습니다.

메트릭 뷰를 설계할 때는 다음 순서로 정리하십시오.

1. 지표 목록과 각 지표의 계산식을 정리합니다. 예: 매출 합계, 고유 고객 수, 그 둘의 비율.
2. 묶음 기준이 될 필드를 정합니다. 예: 날짜, 지역, 제품 카테고리.
3. 원천 테이블과 조인 관계를 정합니다. 스타 스키마인지, 다중 수준 조인이 필요한지 확인합니다.
4. 기간 계산이 필요하면 윈도 측정값을 쓰는지 정합니다.
5. 정의를 SQL DDL로 쓸지, 카탈로그 탐색기 UI에서 만들지 정합니다.

> **참고** DDL 문법과 YAML 구조는 공식 문서의 메트릭 뷰 관리 페이지와 YAML 문법 참고 페이지에서 직접 확인해 작성하십시오. 이 장에서 확인하지 못한 문법을 추측으로 쓰지 않았습니다.

### 메트릭 뷰 권한

메트릭 뷰는 뷰의 권한 규칙을 따릅니다. 이 장에서 확인한 규칙은 다음과 같습니다.

| 항목 | 확인된 내용 |
|---|---|
| 소유권 이전 | 뷰나 메트릭 뷰를 그룹으로 넘기면 협업 편집이 가능해집니다. 공식 문서는 팁으로 설명합니다. |
| 소유권 이전 가능 주체 | 뷰, 함수, 모델은 메타스토어 관리자만 임의의 주체에게 이전할 수 있고, 그 밖의 소유자나 `MANAGE` 보유자는 자기 자신 또는 자기가 속한 그룹으로만 이전할 수 있습니다. |
| 조회 권한 | 권한 참조 페이지는 `SELECT`가 뷰에 적용된다고 설명하며, 뷰 조회에 필요한 상위 카탈로그·스키마 진입 권한은 「권한 모델과 소유권」 페이지와 같습니다. 메트릭 뷰만의 `SELECT` 요구 사항은 이 장에서 확인하지 못했습니다. |

```sql
-- 메트릭 뷰의 소유권을 그룹으로 이전 (뷰 소유권 규칙 적용)
ALTER VIEW mycatalog.myschema.revenue_metrics OWNER TO `finance-team`;
```

> **주의** 위 문장은 뷰 소유권 이전의 일반 형식을 메트릭 뷰에 적용한 예입니다. 메트릭 뷰에서 이 문법이 그대로 동작하는지는 이 장에서 확인하지 않았습니다. 실제 실행 전에 원문에서 확인하십시오.

### 데이터 분류와 메트릭 뷰

데이터 분류(「계보와 데이터 분류」 페이지)는 메트릭 뷰를 **스캔하지 않습니다**. 공식 문서는 메트릭 뷰를 분류 제외 대상으로 명시합니다. 따라서 메트릭 정의가 민감 열을 포함하더라도 분류 태그가 자동으로 붙지 않습니다. 원본 테이블의 분류 결과를 기준으로 판단하고, 메트릭 뷰에 노출되는 필드가 민감하지 않은지 직접 검토하십시오.

## 4. 트레이드오프

### 메트릭 뷰가 맞는 경우

- 같은 지표를 여러 도구에서 같은 정의로 써야 합니다.
- 사용자가 묶음 기준을 자유롭게 고르는 탐색형 분석이 필요합니다.
- 지표 정의를 한곳에서 관리하고 변경 이력을 추적하고 싶습니다.

### 메트릭 뷰가 맞지 않는 경우

- 쿼리 결과가 항상 같은 고정 형태(예: 한 화면의 특정 표)라면 일반 뷰나 테이블이 단순합니다.
- 원천 데이터가 자주 바뀌고 구체화를 설계하기 어렵다면, 쿼리 성능을 실측한 뒤 결정하십시오. 공식 문서는 구체화 기능을 설명하지만 성능 수치는 이 장에서 확인하지 않았습니다.

### 거버넌스 측면의 한계

| 항목 | 내용 |
|---|---|
| 공개 범위 | 공유(OpenSharing)에 메트릭 뷰를 담을 수 있습니다. 2026-09-24 릴리즈 노트는 메트릭 뷰 공유를 GA로 공지했고, 2026-09-03에는 Beta로 공지되었습니다. |
| 분류 | 데이터 분류 스캔 대상이 아닙니다(「거버넌스 태그와 ABAC 정책」 페이지와 「계보와 데이터 분류」 페이지 참조). |
| 상세 권한 | 공식 메트릭 뷰 개요 페이지는 접근 제어, 공동 편집, 수명주기 관리를 언급하지만 권한 이름과 세부 규칙은 싣지 않습니다. 구체 규칙은 Manage metric views 페이지나 UC 거버넌스 문서에서 확인하십시오. |

## 5. 주의사항

> **주의** 메트릭 정의에 원천 테이블의 민감 열이 그대로 들어가면, 메트릭 뷰 조회 권한이 있는 사용자가 민감 값을 집계 형태로 얻을 수 있습니다. 민감 열을 쓸 때는 집계 방식과 노출 범위를 함께 검토하십시오.

> **주의** 메트릭 뷰를 외부로 공유하기 전에 공유 상태 라벨을 확인하십시오. 2026-09-03 공지된 Beta가 2026-09-24에 GA로 전환되었지만, 워크스페이스와 계정 설정에 따라 가용성이 다를 수 있습니다.

- 지표 이름과 계산식은 조직 용어집과 맞춰 정하고, 표시 이름과 동의어는 에이전트 메타데이터에 기록하십시오.
- 메트릭 정의를 바꾸면 그 지표를 쓰는 대시보드와 에이전트 결과가 바뀝니다. 변경 전에 소비처를 확인하십시오(「권한 모델과 소유권」 페이지 권한 회수 주의 참조).
- 구체화를 켜기 전에 갱신 비용과 지연을 원문에서 확인하십시오.
