# 06. Unity Catalog 거버넌스

> 기준일: 2026-10-28 · 근거: 공식 문서 · 수준: 100~300

Unity Catalog(UC)는 Databricks의 데이터와 AI 자산을 한곳에서 관리하는 거버넌스 계층입니다. 테이블, 뷰, 볼륨, 함수, 모델이 모두 같은 3단계 이름(`카탈로그.스키마.객체`) 아래에 놓이고, 누가 무엇을 읽고 쓰고 실행할 수 있는지를 이 계층에서 결정합니다. 이 장은 데이터 엔지니어, 데이터 거버넌스 담당자, 플랫폼 관리자를 대상으로 합니다. UC의 객체 모델과 권한 체계를 이해하고, 태그 기반 접근 제어(ABAC), 행 필터와 열 마스크, 볼륨과 외부 스토리지, 계보, 데이터 분류, 공유, 메트릭 뷰의 정의와 거버넌스 측면까지 설정 단위로 익히는 것이 목표입니다.

## 학습 목표

이 장을 마치면 다음을 할 수 있습니다.

- 메타스토어, 카탈로그, 스키마의 역할과 3단계 이름 체계를 설명하고 UC가 해결하는 문제를 구분합니다.
- 테이블, 뷰, 볼륨, 함수, 모델 등 securable 객체의 종류와 계층 구조를 설명합니다.
- 소유권, 상속, `GRANT`/`REVOKE`, `MANAGE`, `BROWSE` 권한을 설계하고 `USE CATALOG`·`USE SCHEMA` 요구 사항을 빠뜨리지 않습니다.
- 거버넌스 태그(Governed tags)를 정의하고 ABAC 정책으로 태그 기반 행 필터, 열 마스크, GRANT 정책을 설계합니다.
- 테이블 단위 행 필터·열 마스크를 적용하는 방식과 ABAC 정책 방식의 차이를 구분합니다.
- 관리형·외부 볼륨, 스토리지 자격 증명(Storage credential), 외부 위치(External location)의 역할을 구분합니다.
- 계보(Lineage)와 데이터 분류(Data Classification)가 무엇을 기록하고 어떤 제약이 있는지 확인합니다.
- OpenSharing 기반 데이터 공유와 Clean Rooms의 차이를 설명합니다.
- 메트릭 뷰(Metric view)의 정의 방식과 거버넌스 적용 범위를 이해합니다.

## 선수 지식

- **SQL 기초**: `SELECT`, `CREATE`, `GRANT`, `ALTER` 문의 기본 형태를 알고 있어야 합니다.
- **Delta Lake 기초**: 테이블 종류(관리형·외부)와 Delta 테이블의 개념을 알고 있으면 좋습니다.
- **클라우드 스토리지 기초**: S3 버킷, IAM 역할 같은 용어를 알고 있어야 외부 위치와 스토리지 자격 증명을 이해할 수 있습니다.
- **Databricks 워크스페이스 기초**: 워크스페이스, 계정 콘솔, 카탈로그 탐색기(Catalog Explorer)의 위치를 알고 있어야 합니다.

## 이 장의 읽는 법

각 기능 페이지는 같은 구조를 따릅니다. 왜 필요한지, 어떻게 동작하는지, 어떻게 쓰는지, 트레이드오프, 주의사항 순서입니다. 기능마다 상태(GA, Public Preview, Beta)를 표기하고, 상태 라벨이 없으면 "문서에 상태 라벨 없음"으로 적습니다. 라벨이 없다고 GA로 추정하지 않습니다.

> **주의** UC는 릴리즈가 잦은 영역입니다. 2026년 8월부터 10월 사이에도 GA 전환, Beta 신규 공개, 권한 동작 변경이 여러 건 있었습니다. 이 장은 2026-10-28 기준 공식 문서를 확인한 결과이며, 각 페이지 끝의 참고 문서 링크에서 최신 원문을 다시 확인하십시오.
