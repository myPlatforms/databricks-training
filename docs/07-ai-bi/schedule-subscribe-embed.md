# 예약·구독과 임베딩

> 기준일: 2026-10-28 · 근거: 공식 문서

## 한눈에 보기

게시된 대시보드는 세 가지 방식으로 사람에게 닿습니다.

| 방식 | 무엇이 전달되는가 | 누가 받는가 | 상태 |
|---|---|---|---|
| 예약(Schedule) | 정해진 주기마다 데이터를 새로 고치고, 구독자에게 결과를 보냄 | 구독자(이메일, Slack 채널, Teams 채널) | 문서에 상태 라벨 없음 |
| 구독(Subscription) | 예약 실행의 결과(PDF, PNG, CSV, TSV, Excel 첨부) | 작업 공간 사용자, 배포 목록, 외부 사용자(이메일) | 문서에 상태 라벨 없음 |
| 임베딩(Embedding) | 게시된 대시보드를 외부 웹사이트나 앱에 iframe으로 삽입 | 기본 임베딩은 Databricks 로그인 사용자, 외부 사용자는 서비스 프린시펄 인증 | 문서에 상태 라벨 없음 |

예약과 구독은 같은 설정의 두 면입니다. 예약은 "언제 무엇을 새로 계산해 보낼 것인가"이고, 구독은 "누가 받을 것인가"입니다. 임베딩은 대시보드를 다른 화면 안에 넣는 방식입니다.

## 1. 왜 필요한가

### 이전 방식의 한계

- 매주 월요일마다 누군가 대시보드를 열어 PDF로 저장해 메일로 보내는 작업은 사람이 빠지면 멈춥니다.
- 대시보드를 외부 포털에 넣으려면 사용자마다 BI 도구 계정을 만들어야 하는 경우가 많습니다.
- 예약 실행이 어떤 권한으로 도는지 모르면, 메일로 나간 결과가 누구의 데이터인지 설명할 수 없습니다.

AI/BI는 예약을 대시보드 안에서 설정하고, 구독자에게 PDF·이미지·데이터 첨부를 자동으로 보냅니다. 임베딩은 게시본을 iframe으로 제공하고, 외부 사용자는 서비스 프린시펄로 인증하는 경로를 따로 둡니다.

## 2. 어떻게 동작하는가

### 예약

공식 문서가 설명하는 예약의 동작은 다음과 같습니다.

- 대시보드 오른쪽 위의 **Schedule** 에서 빈도, 시작 시각, 시간대를 정합니다. Quartz cron 구문으로 직접 편집할 수도 있습니다.
- 고급 설정에서 이름, SQL 웨어하우스, 현재 필터 선택 적용 여부, 이메일 제목, 구독자, 첨부를 정합니다.
- 각 실행은 데이터셋 뒤의 SQL을 실행하고, 쿼리 결과 캐시를 채웁니다.
- 시작 시각이 있으면 그 시각을 기준으로 하루 단위로 주기를 다시 맞춥니다. 예를 들어 15:10에 시작한 4시간 주기 예약은 15:10, 19:10, 23:10에 실행됩니다.
- 기본 SQL 웨어하우스는 대시보드를 만들고 실행할 때 쓴 웨어하우스를 그대로 이어받습니다.

> **주의** 공식 예약 문서는 예약의 ** 소유자(schedule owner)** 와 예약 실행이 게시자의 자격 증명으로 도는지 뷰어의 자격 증명으로 도는지를 명시하지 않습니다. 이 장에서는 이 부분을 추측해서 쓰지 않습니다. 운영에 쓰기 전에 대상 워크스페이스에서 실행 권한을 직접 확인하십시오. 예약 캐시가 공유 캐시와 개별 캐시로 나뉜다는 설명은 아래에 그대로 옮겼습니다.

### 예약 실행의 캐시

예약 문서는 캐시를 다음과 같이 설명합니다.

- 공유 데이터 권한으로 게시된 대시보드는 **공유 캐시** 를 씁니다.
- 개별 데이터 권한으로 게시된 대시보드에서는 사용자가 **새로 고침 전용 예약**(refresh-only schedule)을 만들어 자기 캐시를 갱신할 수 있습니다.

### 구독자와 구독 옵션

| 항목 | 내용 |
|---|---|
| 이메일 구독자 | 작업 공간 사용자, 배포 목록(distribution list), 외부 사용자. PDF 스냅샷을 받음 |
| Slack·Teams 구독 | 관리자가 알림 대상(notification destination)으로 구성한 채널. PNG 스냅샷, 대시보드 링크, PDF를 스레드에 받음 |
| 구독자 옵션 | Inactive, Refresh data only, Refresh data and email |
| 구독자 수 | 목록당 최대 100명. 알림 대상 하나는 1명으로 계산 |

권한에 따라 구독자 관리 범위가 다릅니다. CAN EDIT 이상은 다른 구독자를 추가하거나 제거할 수 있고, CAN VIEW 이상은 자기 자신만 추가하거나 제거할 수 있습니다.

> **참고** 예약 문서에는 웹훅(Webhook) 대상에 대한 설명이 없습니다. 이 장은 웹훅을 구독 대상으로 쓰지 않습니다.

### 첨부

| 첨부 종류 | 설명 | 한도 |
|---|---|---|
| PDF | 선택한 페이지를 고른 순서대로 포함 | 아래 크기 한도 참고 |
| CSV, TSV, Excel | 결과가 있는 위젯의 데이터. 적용된 필터는 별도 파일로 첨부 가능 | Excel은 100,000행까지 |
| PNG 스냅샷 | Slack·Teams 구독에서 제공 | 문서에 별도 수치 없음 |

첨부 한도는 다음과 같습니다.

- 이메일에 붙이는 첨부 합계(PDF, PNG, CSV, TSV, Excel)는 **9 MB** 입니다. 합계를 넘으면 PDF만 붙고, 대시보드 링크로 대체됩니다.
- PDF가 9 MB를 넘으면 이메일에서 PDF와 이미지가 빠지고 실제 파일 크기를 적은 안내가 붙습니다.
- 표 형식 첨부가 빠지면 이메일에 "were excluded"라는 안내가 들어가고, 사용자는 대시보드를 열어 확인해야 합니다.

### 실행 기록과 일시 중지

- 실행 기록에는 성공(succeeded), 실패(failed), 건너뜀(skipped)이 표시됩니다. 건너뜀은 예약이 동시 실행 한도에 걸렸다는 뜻입니다.
- **일시 중지**(paused)된 예약은 설정과 구독자 설정을 그대로 두고, 재개할 때까지 대시보드를 갱신하지 않으며 알림도 보내지 않습니다.
- 이메일 본문의 구독 해지 링크를 누르면 그 수신 목록 전체가 제거됩니다.
- 예약 이메일로 보낸 PDF는 전달 직후 삭제됩니다. 수동 다운로드 PDF는 최대 60일 보관됩니다.

### PDF 다운로드 한도

게시된 대시보드를 PDF로 내려받을 때 한도는 다음과 같습니다.

| 항목 | 한도 | 초과 시 |
|---|---|---|
| PDF 파일 크기 | 50 MB | 선택한 페이지가 넘으면 첫 페이지만 포함되고 경고가 표시됨. 첫 페이지 자체가 넘으면 다운로드 실패 |
| 생성 시간 | 30분 | 넘으면 "Could not generate PDF." 오류 |

2026-10-22 릴리즈 노트에 따르면 PDF 다운로드 시 특정 페이지나 전체 페이지를 고를 수 있습니다. 라벨은 없습니다.

### 임베딩

공식 임베딩 문서는 두 방식을 설명합니다.

| 구분 | 방식 | 인증 | 데이터 권한 |
|---|---|---|---|
| 기본 임베딩(Basic embedding) | Share 대화 상자에서 iframe 코드를 생성해 삽입 | 뷰어가 Databricks 계정으로 로그인 | 뷰어에게 대시보드 접근 권한이 필요 |
| 외부 사용자 임베딩(Embedding for external users) | 애플리케이션이 서비스 프린시펄과 OAuth 시크릿으로 인증 | 뷰어는 Databricks 계정이 필요 없음 | 개별 데이터 권한을 권장 |

임베딩의 공통 조건은 다음과 같습니다.

- **게시본만 임베드할 수 있습니다.**
- 워크스페이스 관리자가 **허용된 임베딩 표면**(allowed embedding surfaces)을 먼저 정해야 합니다.
- 뷰어의 브라우저에서 **서드파티 쿠키** 가 켜져 있어야 합니다. 꺼져 있으면 iframe이 빈 화면으로 보일 수 있습니다.
- 외부 사용자 임베딩의 액세스 토큰은 **1시간** 동안 유효하다고 문서에 나옵니다.
- 색 구성(colorScheme)은 `light`(기본), `dark`, `light dark` 중 고를 수 있습니다.

외부 사용자 임베딩에서 쿼리는 게시자의 권한이 아니라 개별 데이터 권한으로 실행되는 것이 권장 방식입니다. 문서는 공유 권한을 쓰면 "the publisher's permissions are used for data access, not the service principal's."라고 설명합니다.

### 임베딩과 Ask Genie

Ask Genie 지원 여부는 임베딩 방식에 따라 다릅니다. 기본 임베딩은 지원되고, 외부 사용자 임베딩은 지원되지 않습니다. 외부 사용자 임베딩에서 대화형 기능이 필요하면 Genie Conversation API를 쓰도록 문서가 안내합니다.

2026-09-03 릴리즈 노트에 따르면, 임베디드 대시보드에서 지원하지 않는 Ask Genie 버튼은 숨겨집니다. 같은 날짜에 임베디드 대시보드의 필터 값을 API로 설정하고 조회할 수 있게 되었습니다. 2026-10-01 릴리즈 노트에 따르면 임베디드 대시보드는 글로벌 필터를 기본적으로 표시, 접기, 숨기기 중 하나로 설정할 수 있습니다.

### Genie Agent 임베딩

Genie Agent도 iframe으로 삽입할 수 있습니다. 공식 문서 절차는 다음과 같습니다.

1. Genie Agent를 열고 **Share** 를 누릅니다.
2. **Embed space** 를 눌러 iframe 코드를 복사합니다.
3. 사이트나 앱에 붙여 넣습니다. 클립보드 복사 기능(CSV 복사, 대화 링크 복사)을 쓰려면 iframe에 `allow="clipboard-write"` 속성을 넣습니다.

사전 조건은 다음과 같습니다.

- 워크스페이스 관리자가 Genie 접근 관리 설정에서 허용된 임베딩 표면을 정합니다.
- 작성자는 Genie Agent에 최소 CAN MANAGE 권한이 있어야 합니다.
- 최종 사용자는 Genie Agent와 기반 데이터에 명시적 접근 권한이 있어야 합니다. 문서는 "Users only see data they have permission to access."라고 명시합니다.
- 로그인하지 않은 사용자는 임베드된 에이전트와 대화하기 전에 인증을 거칩니다.

> **참고** Genie Agent 임베딩 문서는 서비스 프린시펄이나 OAuth 인증, 상태 라벨을 다루지 않습니다. 외부 앱에 Genie Agent를 붙이는 설계는 Genie Conversation API 문서와 함께 확인하십시오.

## 3. 어떻게 쓰는가

### 예약 설정 순서

1. 게시된 대시보드를 엽니다.
2. 오른쪽 위 **Schedule** 을 누릅니다.
3. 빈도와 시작 시각, 시간대를 정합니다. 복잡한 주기는 Quartz cron 구문으로 편집합니다.
4. 고급 설정에서 SQL 웨어하우스와 현재 필터 적용 여부를 정합니다.
5. 구독자를 추가합니다. 이메일, Slack·Teams 채널 중에서 고릅니다.
6. 첨부(PDF의 페이지, CSV·TSV·Excel 데이터)를 고릅니다.
7. 실행 기록에서 첫 실행이 성공했는지 확인합니다.

### 임베딩 설정 순서(기본 임베딩)

1. 대시보드를 게시합니다. 초안은 임베드할 수 없습니다.
2. 워크스페이스 관리자가 허용된 임베딩 표면을 등록했는지 확인합니다.
3. Share 대화 상자에서 iframe 코드를 생성합니다.
4. 외부 사이트에 삽입하고, 뷰어가 쿠키를 허용한 상태에서 열리는지 확인합니다.

## 4. 트레이드오프

- **예약은 편하지만 실행 주체가 불분명합니다.** 문서가 소유자와 자격 증명을 명시하지 않으므로, 민감 데이터를 메일로 보내는 예약은 운영 전에 권한 테스트를 하십시오.
- **구독은 PDF 중심이라 가독성이 제한됩니다.** 9 MB 합계를 넘기면 PDF가 빠지고 링크만 남습니다. 표 데이터가 많으면 Excel을 따로 쓰는 편이 낫습니다.
- **외부 사용자 임베딩은 서비스 프린시펄과 개별 권한이 필요합니다.** 설정 비용이 큽니다. 내부 사용자 대상이면 기본 임베딩이 단순합니다.
- **Ask Genie는 기본 임베딩에서만 지원됩니다.** 외부 사용자에게 대화형 질문 기능이 필요하면 설계를 나눠야 합니다.

### 언제 쓰지 않는가

- 실시간으로 바뀌는 화면이 필요하면 예약 주기보다 대시보드의 수동 새로 고침이나 별도 애플리케이션을 검토하십시오.
- 메일 한 통으로 수백 개 행을 보내려는 경우에는 Excel 100,000행 한도에 걸릴 수 있습니다.

## 5. 주의사항

- **예약의 실행 주체를 먼저 확인합니다.** 문서에 명시되지 않으므로, 대상 워크스페이스에서 테스트 예약으로 확인하십시오.
- **구독자 목록을 관리합니다.** 목록당 100명 한도가 있고, 알림 대상도 한 명으로 계산됩니다.
- **일시 중지를 기억합니다.** 일시 중지된 예약은 조용히 멈추므로 운영 점검 목록에 넣으십시오.
- **임베딩 전에 허용 표면을 확인합니다.** 관리자 설정 없이 iframe만 붙이면 동작하지 않습니다.
- **서드파티 쿠키를 확인합니다.** 빈 iframe은 대부분 이 설정 때문입니다.
- **외부 사용자 토큰은 1시간입니다.** 토큰 갱신 로직을 애플리케이션에 넣으십시오.
- **임베딩 기능의 라벨을 확인합니다.** 임베딩 문서 페이지에는 상태 라벨이 없습니다. 릴리즈 노트의 항목과 함께 확인하십시오.
