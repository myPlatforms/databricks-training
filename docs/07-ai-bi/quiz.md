# 퀴즈와 체크리스트

> 기준일: 2026-10-29 · 근거: 이 장 본문 · 수준: 100~300

이 장에서 다룬 내용을 확인하는 문제입니다. 정답을 펼치면 해설과 근거 페이지로 가는 링크가 있습니다.

## 퀴즈

### 1. 매일 같은 KPI를 같은 필터로 보는 용도에 가장 맞는 AI/BI 제품은 무엇인가? (수준 100)

- A. Genie Agents
- B. AI/BI 대시보드
- C. Genie One
- D. Genie Code

<details markdown="1">
<summary>정답과 해설</summary>

**정답: B** — 대시보드는 정해진 시각화와 주기적 스냅샷에 맞습니다. Genie Agents는 질문마다 답을 만드는 대화형 작업 공간이므로 열린 질문에 맞고, Genie One은 대시보드·Genie·Databricks Apps를 모은 현업용 진입점입니다. Genie Code는 개발과 기술 사용자를 돕는 어시스턴트입니다.

근거: [AI/BI 개요와 제품 구분 — 어떤 제품을 고를지 정하기](what-is-ai-bi.md#어떤-제품을-고를지-정하기)

</details>

### 2. Genie One에 대한 설명으로 옳은 것은? (수준 100)

- A. 질문마다 SQL을 만들어 답하는 대화형 작업 공간이다.
- B. 대시보드, Genie 기반 데이터 질문, Databricks Apps를 한곳에 모은 통합 진입점이다.
- C. Genie Agents의 이전 이름이다.
- D. 개발자가 대시보드와 Genie 설정을 만들 때 쓰는 코딩 어시스턴트이다.

<details markdown="1">
<summary>정답과 해설</summary>

**정답: B** — 본문은 Genie One을 비즈니스 사용자용 소비 인터페이스이자 통합 진입점으로 설명합니다. A는 Genie Agents의 설명이고, C는 Genie Agents의 이전 명칭인 Genie Spaces와 혼동한 보기입니다. D는 Genie Code의 설명입니다.

근거: [AI/BI 개요와 제품 구분 — 제품 관계](what-is-ai-bi.md#제품-관계)

</details>

### 3. AI/BI 구성 요소들이 공통으로 가진 특징은 무엇인가? (수준 100)

- A. 데이터를 각 제품의 외부 BI 엔진으로 추출해 복제해 둔다.
- B. 사용자 수에 따라 좌석 기반 라이선스가 필요하다.
- C. Genie 답변은 항상 같은 SQL이 나오므로 결정적이다.
- D. 같은 Unity Catalog 데이터 위에서 동작하며, 구성 요소 모두 UC가 거버넌스한다.

<details markdown="1">
<summary>정답과 해설</summary>

**정답: D** — 본문은 AI/BI가 같은 UC 데이터 위에서 동작하고, 이 모든 구성 요소를 UC가 거버넌스한다고 설명합니다. 데이터 추출이 필요 없다는 점도 장점으로 적혀 있습니다. A는 본문이 말하는 "데이터 추출 불필요"와 반대이고, B는 본문이 좌석 기반 제한이 없다고 설명한 내용과 반대입니다. C는 Genie가 생성형 시스템이라 질문 표현에 따라 답이 달라질 수 있다는 본문 설명과 어긋납니다.

근거: [AI/BI 개요와 제품 구분 — 플랫폼 통합에서 얻는 것](what-is-ai-bi.md#플랫폼-통합에서-얻는-것)

</details>

### 4. 메트릭 뷰를 대시보드 데이터셋으로 쓸 때 가장 올바른 방법은 무엇인가? (수준 200)

- A. 데이터셋 쿼리를 편집해 필요 없는 열을 뺀다.
- B. 대시보드 필터 위젯이나 파라미터로 범위를 제한한다.
- C. SQL 편집기에서도 측정값을 `MEASURE()` 없이 바로 참조한다.
- D. 메트릭 뷰에 다른 테이블을 직접 조인한 뒤 데이터셋으로 등록한다.

<details markdown="1">
<summary>정답과 해설</summary>

**정답: B** — 메트릭 뷰 데이터셋에는 정의된 차원과 측정값이 모두 들어가며, 그 쿼리는 열을 빼거나 필터를 더하도록 편집할 수 없습니다. 필요한 범위는 필터 위젯이나 파라미터로 처리합니다. A는 편집 불가라는 본문 설명과 반대입니다. C는 SQL 편집기에서 모든 측정값을 `MEASURE()`로 감싸야 한다는 규칙과 어긋납니다. D는 메트릭 뷰 쿼리가 다른 테이블과 쿼리 시점에 직접 조인될 수 없다는 본문 설명과 어긋납니다.

근거: [메트릭 뷰 소비하기 — 쿼리 규칙](metric-views-in-ai-bi.md#쿼리-규칙), [대시보드 작성 — 데이터셋의 종류](dashboard-authoring.md#데이터셋의-종류)

</details>

### 5. 뷰어마다 다른 행을 봐야 하는 대시보드를 게시할 때 가장 적절한 설정은 무엇인가? (수준 200)

- A. 게시 기본값인 공유 데이터 권한을 그대로 둔다.
- B. 개별 데이터 권한으로 게시한다.
- C. 초안 상태로 공유해 뷰어가 각자 권한으로 보게 한다.
- D. 계정 전체 공유 옵션을 켠다.

<details markdown="1">
<summary>정답과 해설</summary>

**정답: B** — 공유 데이터 권한에서는 쿼리가 게시자의 자격 증명으로 실행되므로, 행 필터 평가 기준도 게시자가 됩니다. 뷰어마다 다른 행이 보여야 하면 뷰어 자격 증명으로 실행되는 개별 데이터 권한을 씁니다. C의 초안은 게시 설정과 무관하게 작성자와 권한이 있는 사용자만 보며, 뷰어에게 변경이 반영되려면 다시 게시해야 합니다. D의 계정 전체 공유는 공유 범위의 문제이지 데이터 권한 평가 기준을 바꾸지 않습니다.

근거: [게시와 데이터 권한 — 두 방식 비교](publish-and-permissions.md#두-방식-비교)

</details>

### 6. 외부 사용자(Databricks 계정이 없는 사용자)에게 대시보드를 임베드하는 방식에 대한 설명으로 옳은 것은? (수준 200)

- A. 뷰어가 Databricks 계정으로 로그인해야 한다.
- B. 애플리케이션이 서비스 프린시펄로 인증하며, 데이터 권한은 개별 데이터 권한을 쓰는 것이 권장된다.
- C. 게시하지 않은 초안도 iframe으로 삽입할 수 있다.
- D. 기본 임베딩과 마찬가지로 Ask Genie 버튼이 동작한다.

<details markdown="1">
<summary>정답과 해설</summary>

**정답: B** — 외부 사용자 임베딩은 애플리케이션이 서비스 프린시펄과 OAuth 시크릿으로 인증하고, 뷰어는 Databricks 계정이 없어도 됩니다. 데이터 권한은 개별 데이터 권한을 권장합니다. A는 기본 임베딩의 설명입니다. C는 임베드는 게시본만 가능하다는 본문 설명과 어긋납니다. D는 외부 사용자 임베딩에서 Ask Genie가 지원되지 않는다는 본문 설명과 어긋납니다.

근거: [예약·구독과 임베딩 — 임베딩](schedule-subscribe-embed.md#임베딩), [예약·구독과 임베딩 — 임베딩과 Ask Genie](schedule-subscribe-embed.md#임베딩과-ask-genie)

</details>

### 7. 정형 테이블의 단순 질문에는 Chat mode로 충분하지만, 볼륨의 비정형 파일을 다루거나 여러 쿼리가 필요한 다단계 분석을 해야 할 때 맞는 선택은 무엇인가? (수준 200)

- A. Chat mode를 그대로 쓰고 질문을 여러 번 나눈다.
- B. Agent mode를 쓴다.
- C. 대시보드 위젯으로 바꾼다.
- D. 질문을 SQL 웨어하우스 대신 노트북에서 실행한다.

<details markdown="1">
<summary>정답과 해설</summary>

**정답: B** — 본문은 Chat mode가 정형 데이터의 단순 질문에 맞고, 비정형 파일과 MCP 커넥터, 다단계 분석은 할 수 없다고 설명합니다. 여러 쿼리가 필요한 복잡한 질문, 볼륨 파일, 외부 도구는 Agent mode의 범위입니다. A는 Chat mode의 한계를 질문 나누기로 피하려는 보기입니다. C와 D는 본문이 이 상황의 해법으로 제시하지 않습니다.

근거: [Genie Agents 만들기 — 두 가지 실행 모드](genie-agents-setup.md#두-가지-실행-모드)

</details>

### 8. 정확한 KPI 계산식(예: 승률, 반올림 규칙이 얽힌 매출 지표)을 Genie Agent가 여러 질문에서 같은 방식으로 적용하게 하려면 어디에 정의하는 것이 가장 적절한가? (수준 300)

- A. 일반 인스트럭션에 계산식을 문장으로 길게 적는다.
- B. 질문을 던질 때마다 사용자가 프롬프트에 계산식을 넣게 한다.
- C. 지식 저장소의 SQL 식(Measures 등)으로 정의한다.
- D. 벤치마크 점수가 높아지도록 질문과 답을 맞춰 둔다.

<details markdown="1">
<summary>정답과 해설</summary>

**정답: C** — 본문은 정확한 비즈니스 규칙(KPI 계산식, 임계값, 분류)은 텍스트 인스트럭션보다 SQL 식으로 정의하라고 권장합니다. Genie가 SQL 식을 적은 그대로 적용한다는 설명이 근거입니다. A는 텍스트 설명이 모호하거나 충돌할 수 있다는 본문 설명과 어긋나고, 일반 인스트럭션은 모든 질문에 공통으로 적용할 맥락을 담는 용도입니다. B는 일관성을 보장하지 못합니다. D는 벤치마크가 설정을 측정하는 도구이며 설정을 자동으로 고쳐 주지 않는다는 본문 설명과 어긋납니다.

근거: [Genie Agents 신뢰도 높이기 — 지식 저장소](genie-agents-quality.md#3-4-지식-저장소-한도-200개), [Genie Agents 신뢰도 높이기 — 트레이드오프](genie-agents-quality.md#4-트레이드오프)

</details>

### 9. Power BI 보고서가 메트릭 뷰의 BI 호환 모드에 의존하고 있다면, 가장 먼저 해야 할 일은 무엇인가? (수준 300)

- A. 기존 설정이 계속 동작하므로 그대로 둔다.
- B. Power BI 커넥터에서 BI 호환 모드 옵션을 다시 켠다.
- C. 의존성을 점검하고, Native query와 `MEASURE()`를 쓰는 DirectQuery 방식으로 전환을 검토한다.
- D. 메트릭 뷰를 삭제하고 보고서를 처음부터 다시 만든다.

<details markdown="1">
<summary>정답과 해설</summary>

**정답: C** — 본문은 Microsoft가 Databricks 커넥터에서 Metric View BI Compatibility Mode 옵션을 제거했으며, 그 옵션을 쓰던 보고서는 더 이상 동작하지 않는다고 설명합니다. 대체 방법으로 커넥터의 Native query와 DirectQuery 모드의 `MEASURE()` 패턴을 안내합니다. A는 본문과 어긋나고, B는 옵션이 제거되었으므로 불가능합니다. D는 본문이 제시하는 대안이 아닙니다.

근거: [외부 BI 도구와 병행 — 도구별 연결 방식](external-bi-tools.md#도구별-연결-방식)

</details>

## 실무 체크리스트

이 장의 내용을 실제 환경에 적용할 때 확인할 항목입니다.

- [ ] 대시보드를 게시하기 전에 데이터 민감도를 보고 공유 데이터 권한과 개별 데이터 권한 중 하나를 의도적으로 고른다 — [게시와 데이터 권한](publish-and-permissions.md#두-방식-비교)
- [ ] 예약의 실행 주체(게시자 또는 뷰어 자격 증명)를 대상 워크스페이스에서 테스트 예약으로 직접 확인한다 — [예약·구독과 임베딩](schedule-subscribe-embed.md#예약)
- [ ] 임베딩 전에 워크스페이스 관리자가 허용된 임베딩 표면을 등록했는지 확인하고, 뷰어 브라우저의 서드파티 쿠키 설정을 점검한다 — [예약·구독과 임베딩](schedule-subscribe-embed.md#임베딩)
- [ ] Genie Agent의 데이터 소스는 질문 범위에 맞는 테이블만 붙이고, 공유 전에 예제 SQL·인스트럭션·지식 저장소를 채운다 — [Genie Agents 만들기](genie-agents-setup.md#공유)
- [ ] 신뢰 자산으로 쓰는 UC SQL 함수에 에이전트 사용자의 `EXECUTE` 권한이 있는지 확인한다 — [Genie Agents 신뢰도 높이기](genie-agents-quality.md#3-2-예제-sql과-신뢰-자산)
- [ ] 메트릭 뷰를 SQL로 쿼리할 때 모든 측정값을 `MEASURE()`로 감싸고, 다른 테이블과의 조인은 CTE로 분리했는지 확인한다 — [메트릭 뷰 소비하기](metric-views-in-ai-bi.md#쿼리-규칙)
- [ ] 알림 웹훅 수신 측이 `ERROR` 상태를 `OK`와 구분하고, 선택 필드가 없을 수 있다는 전제로 구현되었는지 확인한다 — [알림](alerts.md#웹훅-페이로드)
- [ ] 알림 소유자가 워크스페이스에서 제거되지 않았는지 정기적으로 점검하고, 필요하면 소유권을 이전한다 — [알림](alerts.md#공유-권한-소유권)
- [ ] 기존 Power BI 보고서가 BI 호환 모드에 의존하는지 찾아 전환 계획을 세운다 — [외부 BI 도구와 병행](external-bi-tools.md#도구별-연결-방식)
- [ ] 대시보드의 페이지·데이터셋·위젯 한도를 설계 단계에서 확인하고, 넘을 경우 대시보드를 나누는 방안을 정한다 — [대시보드 작성](dashboard-authoring.md#주요-한도)
