# <img src="https://www.databricks.com/sites/default/files/2025-08/primary-icon-orange-predictive-analytics.svg" alt="" width="40" class="chapter-icon"> 07. AI/BI (대시보드·Genie)

> 기준일: 2026-10-28 · 근거: 공식 문서 · 수준: 100~300

AI/BI는 Databricks의 분석·소비 계층입니다. 정해진 질문에 답하는 **AI/BI 대시보드**(AI/BI dashboards)와 자연어로 데이터를 묻는 **Genie Agents** 가 같은 Unity Catalog 데이터 위에서 동작합니다. 여기에 비즈니스 사용자용 진입점인 **Genie One** 이 더해집니다. 이 장은 이 제품들을 어떻게 구성하고, 어떻게 게시하고, 어떻게 신뢰도를 높이고, 메트릭 뷰와 외부 BI 도구를 어떻게 함께 쓰는지를 다룹니다.

이 장은 데이터 분석가, BI 개발자, 데이터 제품 담당자, 현업 사용자를 지원하는 플랫폼 담당자를 대상으로 합니다. 대시보드를 만들고 배포하는 방법, Genie Agent를 설계하고 평가하는 방법, 그리고 권한과 비용에 영향을 주는 설정을 이해하는 것이 목표입니다.

## 학습 목표

이 장을 마치면 다음을 할 수 있습니다.

- AI/BI 대시보드, Genie Agents, Genie One, Ask Genie, Genie Code가 각각 무엇을 위한 제품인지 구분합니다.
- 대시보드의 데이터셋, 위젯, 필터, 파라미터의 관계를 설명하고 한도(페이지, 데이터셋, 행 수)를 확인합니다.
- 대시보드를 **공유 데이터 권한**(게시자 자격 증명)과 **개별 데이터 권한**(뷰어 자격 증명) 중 어느 쪽으로 게시할지 판단합니다.
- 예약, 구독, 임베딩이 어떤 자격 증명으로 실행되는지 확인하고 설정합니다.
- Genie Agent를 데이터 소스, 인스트럭션, 예제 SQL, 지식 저장소로 구성하고 공유합니다.
- 벤치마크와 모니터링으로 Genie Agent의 답변 정확도를 측정하고 개선합니다.
- 메트릭 뷰를 대시보드, Genie Agent, 외부 BI 도구에서 소비하는 방법을 고르고, 정의와 거버넌스는 06장에서 확인합니다.
- 알림(Alerts)의 상태 전이와 설정 단위를 이해합니다.
- Power BI, Tableau 같은 외부 BI 도구와 AI/BI를 병행할 때의 연결 방식과 제약을 구분합니다.

## 이 장의 범위 밖

- **대시보드·Genie의 코드형 관리**(Declarative Automation Bundles, REST API, Git 연동): 11장에서 다룹니다. 이 장은 UI에서의 작성·게시·운영을 기준으로 씁니다.
- **Genie Code의 사용법과 과금**: [11장 Genie Code](../11-developer-tools/genie-code/README.md)에서 다룹니다. 이 장에서는 Genie Code가 대시보드와 Genie Agent 생성, 메트릭 뷰 가져오기에 쓰인다는 점만 짚습니다.
- **메트릭 뷰 정의와 거버넌스**(YAML·DDL, 권한, 공유): [06장 메트릭 뷰의 거버넌스](../06-unity-catalog/metric-views-governance.md)에서 다룹니다.
- **시스템 테이블과 감사 로그**: 12장에서 다룹니다.

> **참고** 이 장의 근거는 AWS 공식 문서(`docs.databricks.com/aws/en/`)입니다. Azure Databricks 문서에서 가용성이나 상태 라벨이 다를 수 있으므로, 대상 클라우드의 원문을 확인하십시오.

## 선수 지식

- **SQL 기초**: `SELECT`, `GROUP BY`, `WHERE`, 집계 함수를 알고 있어야 합니다. 메트릭 뷰 쿼리는 이 문법을 기반으로 합니다.
- **Unity Catalog 기초**: 3단계 이름(`카탈로그.스키마.객체`)과 `SELECT` 권한의 의미를 알고 있어야 합니다. 06장 1~2페이지를 먼저 보면 좋습니다.
- **BI 기초**: 차원(dimension)과 측정값(measure), 필터, 대시보드 게시의 개념을 알고 있으면 빠르게 이해할 수 있습니다.
- **SQL 웨어하우스 기초**: 대시보드와 Genie Agent가 쿼리를 실행하는 컴퓨트가 SQL 웨어하우스라는 점을 알고 있어야 합니다. 03장의 [SQL 웨어하우스](../03-compute/sql-warehouses.md) 페이지를 참고하십시오.

## 이 장의 읽는 법

각 기능 페이지는 왜 필요한지, 어떻게 동작하는지, 어떻게 쓰는지, 트레이드오프, 주의사항 순서로 씁니다. 기능마다 상태 라벨(GA, Public Preview, Beta)을 표기합니다. 공식 문서에 라벨이 없으면 "문서에 상태 라벨 없음"이라고 적고, 라벨이 없다고 GA로 추정하지 않습니다.

> **주의** AI/BI는 릴리즈가 매우 잦은 영역입니다. 2026년 8~10월 사이에도 라벨 변경, 한도 상향, 명칭 변경이 여러 건 있었습니다. 이 장은 2026-10-28 기준 공식 문서를 확인한 결과이며, 실제 설계 전에 각 페이지의 참고 문서 링크에서 최신 원문을 확인하십시오.
