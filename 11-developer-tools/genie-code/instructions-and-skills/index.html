    인스트럭션과 스킬¶

    기준일: 2026-10-28 · 근거: 공식 문서

    왜 필요한가¶

    Genie Code는 기본 설정으로도 쓸 수 있지만, 팀의 코딩 규칙이나 데이터 명명 규칙, 자주 반복하는 작업 절차는 매번 채팅에 적기 어렵습니다. 같은 설명을 반복하면 응답 품질이 흔들리고, 사람마다 다른 지침이 섞입니다.

    두 가지 장치로 이 문제를 줄입니다.

    • 인스트럭션(Instructions): 항상 적용되는 선호와 규칙을 Markdown 파일에 씁니다. 매 응답의 배경 지식이 됩니다.
    • 스킬(Agent skills): 특정 작업 절차를 폴더 단위로 묶습니다. 요청과 설명이 맞을 때 불러오거나, @로 직접 호출합니다.

    두 장치는 모두 저장소나 노트북이 아니라 워크스페이스 파일 경로 에 놓입니다. 그래서 팀 전체가 같은 지침을 공유할 수 있습니다.

    인스트럭션¶

    파일 위치와 권한¶

    종류 경로 편집 권한 적용 범위
    사용자 인스트럭션 /Users/<username-or-email>/.assistant_instructions.md 본인만 본인과의 상호작용에만 적용
    워크스페이스 인스트럭션 /Workspace/.assistant_workspace_instructions.md (문서 표기: 워크스페이스의 Workspace/ 디렉터리) 워크스페이스 관리자만 편집. 다른 사용자는 보기 가능 워크스페이스 전체

    우선순위와 한도¶

    항목 규칙
    우선순위 문서에 따르면 워크스페이스 인스트럭션이 사용자 인스트럭션보다 우선합니다. 명시적으로 다르게 지시하지 않는 한 그렇다고 설명합니다.
    글자 수 한도 20,000자. 한도를 넘는 부분은 무시됩니다.
    형식 Markdown 파일

    AGENTS.md와 CLAUDE.md 자동 로드¶

    설정이 없어도 Genie Code는 AGENTS.md와 CLAUDE.md 파일을 자동으로 찾아 읽습니다. 노트북이나 파일을 열면 해당 위치에서 상위 디렉터리를 거슬러 올라가며, 찾은 인스트럭션 파일의 내용을 컨텍스트에 추가합니다.

    이 규칙은 Git 폴더 구조를 쓰는 팀에 편리합니다. 프로젝트 루트에 AGENTS.md를 두면 그 아래 노트북 모두에 적용됩니다.

    주의 문서는 Quick Fix와 자동완성(Autocomplete)에는 인스트럭션이 적용되지 않는다고 명시합니다. 인스트럭션으로 자동완성 스타일을 맞추려 하면 기대와 다릅니다.

    편집 방법¶

    1. 워크스페이스 우상단의 Genie Code 아이콘을 엽니다.
    2. 패널의 톱니바퀴 아이콘을 누릅니다.
    3. 사용자 인스트럭션은 Add instructions file(파일이 없을 때) 또는 Open instructions file 을 누릅니다.
    4. 워크스페이스 인스트럭션은 View file 을 누릅니다. 관리자만 여기서 편집할 수 있습니다.

    변경 후 새 채팅이 필요한지는 문서에 명시되어 있지 않습니다. 문서는 Genie Code가 다음 상호작용에서 변경을 반영한다고만 설명합니다.

    작성 예시¶

    아래는 사용자 인스트럭션 파일의 예시입니다. 내용은 예시이며 문서가 정한 형식이 아닙니다. 문서는 Markdown 파일이라는 점과 글자 수 한도만 정합니다.

    # 작업 규칙

- SQL은 CTE(WITH 절)로 단계를 나누고, 마지막 SELECT에 주석을 답니다.
- 테이블 이름은 `<catalog>.<schema>.<table>` 형식의 완전한 이름을 씁니다.
- Python 코드는 함수 단위로 나누고, 주석은 영어로 씁니다.
- 날짜 컬럼은 KST 기준으로 해석합니다. 변환이 필요하면 먼저 물어봅니다.
- 운영 카탈로그(`prod`)에 쓰기 작업을 만들기 전에는 반드시 확인을 요청합니다.

    워크스페이스 인스트럭션에는 팀 공통 규칙을, 사용자 인스트럭션에는 개인 선호를 넣는 식으로 나눕니다. 두 파일의 내용이 충돌하면 문서 기준으로 워크스페이스 인스트럭션이 우선합니다.

    스킬 (Agent skills)¶

    경로¶

    범위 경로 가시성
    워크스페이스 스킬 /Workspace/.assistant/skills/<skill-name>/SKILL.md 워크스페이스의 모든 사용자
    사용자 스킬 /Users/<username>/.assistant/skills/<skill-name>/SKILL.md 본인만

    SKILL.md 구조¶

    스킬은 하위 폴더 하나가 스킬 하나입니다. 폴더 안에 SKILL.md 파일이 필수입니다.

    ---
name: skill-name
description: 이 스킬이 무엇을 하는지, 언제 쓰는지 한두 문장으로 씁니다.
---

## 절차

1. 대상 테이블의 스키마를 먼저 확인합니다.
2. ...

## 예시

- 입력: ...
- 기대 출력: ...

## 예외 상황

- ...
    요소 규칙
    frontmatter name 필수
    frontmatter description 필수. Genie Code가 스킬을 언제 불러올지 판단하는 근거이므로 구체적으로 씁니다.
    본문 Markdown. 문서는 단계별 절차, 예시(입력과 기대 출력), 예외 상황을 권장합니다.
    보조 파일 스크립트와 문서(모범 사례, 템플릿)를 함께 둘 수 있습니다. 스킬 폴더 기준 상대 경로로 참조합니다. 문서는 반복 실행 작업은 스크립트로, 지침은 Markdown으로 두라고 권장합니다.

    불러오기 방식¶

    방식 동작
    자동 요청 내용과 스킬의 description이 맞으면 Genie Code가 스킬을 불러옵니다.
    명시 호출 채팅에서 @로 스킬 이름을 언급합니다.

    등록과 갱신¶

    • 스킬 폴더를 여는 방법: 패널의 Settings → Open skills folder.
    • 추가 폴더 등록: Settings 에서 ** 스킬 폴더들을 담은 상위 폴더** 를 등록합니다. 예를 들어 /Users/<username>/my-skills/처럼 하위에 스킬 폴더가 여러 개 있는 경로입니다. 문서는 SKILL.md가 바로 들어 있는 폴더를 등록하지 말라고 명시합니다. 등록된 폴더는 추가 방식이며, 스킬마다 켜고 끌 수 있습니다.
    • 새 스킬: 다음 사용 시 인식됩니다.
    • 기존 스킬 수정: 새 채팅을 열어야 반영됩니다. 문서는 수정이 "don't take effect in active chats"라고 설명합니다.
    • 설명이 예전 내용으로 남아 보이면 브라우저 탭을 강제 새로고침합니다.

    참고 문서에는 스킬 업로드 기능이 나오지 않습니다. 문서가 설명하는 방식은 폴더와 파일을 경로에 직접 만드는 것입니다.

    문서에 없는 것¶

    • 스킬 파일 크기 한도
    • 스킬 상태 라벨(GA, Preview, Beta)
    • 스킬 안 스크립트 실행 시 승인 동작

    트레이드오프¶

    선택 장점 제약
    인스트럭션 항상 적용되어 설정이 단순합니다. AGENTS.md를 쓰면 저장소와 함께 버전 관리됩니다. 한도 20,000자. Quick Fix와 자동완성에는 적용되지 않습니다.
    스킬 절차를 재사용하고, 필요할 때만 불러옵니다. 불러오기 판단이 description에 달려 있어, 설명이 모호하면 안 불러옵니다.
    메모리 작업 중 자동 수집됩니다. 저장 위치와 범위가 문서에 없습니다. 팀 공통 규칙에는 인스트럭션이 맞습니다.

    인스트럭션과 메모리의 차이는 모드·기능과 데이터 접근 권한에서 정리했습니다.

    어떻게 쓰는가 (예시 흐름)¶

    1. 팀 공통 규칙을 워크스페이스 인스트럭션에 씁니다. 관리자가 View file 로 편집합니다.
    2. 개인 선호는 사용자 인스트럭션에 씁니다.
    3. 반복 절차(예: 데이터 품질 점검)를 /Workspace/.assistant/skills/data-quality-check/SKILL.md로 만듭니다.
    4. 설명 문장에 "품질 점검", "결측치 비율" 같은 실제 요청 표현을 넣습니다.
    5. 스킬을 수정하면 새 채팅을 열고 @data-quality-check로 명시 호출해 확인합니다.

    주의사항¶

    • Quick Fix와 자동완성은 인스트럭션을 읽지 않습니다. 자동완성 규칙을 인스트럭션에 넣지 않습니다.
    • 20,000자 한도를 넘기면 뒤쪽이 잘립니다. 긴 규칙은 스킬로 나누는 것을 검토합니다.
    • 수정은 새 채팅에서 확인합니다. 활성 채팅에서는 스킬 수정이 반영되지 않는다고 문서가 명시합니다.
    • 스킬 설명은 구체적으로 씁니다. 자동 불러오기는 설명에 의존합니다.
    • 워크스페이스 스킬은 모든 사용자에게 보입니다. 개인 정보나 자격 증명을 넣지 않습니다.
    • CLI와 워크스페이스는 스킬을 공유하지 않습니다. CLI는 로컬 폴더의 스킬만 읽습니다. 자세한 내용은 Genie Code CLI를 참고하십시오.
