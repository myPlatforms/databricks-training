    게시와 데이터 권한¶

    기준일: 2026-10-28 · 근거: 공식 문서 · 수준: 200

    한눈에 보기¶

    AI/BI 대시보드는 초안(draft)과 게시본(published)으로 나뉩니다. 작성자는 초안을 고치고, 게시하면 뷰어에게 보이는 고정된 스냅샷이 만들어집니다. 게시 시점에 정해야 할 핵심 질문은 하나입니다. 쿼리를 누구의 데이터 권한으로 실행할 것인가 입니다.

    게시 설정 쿼리를 실행하는 자격 증명 뷰어에게 필요한 데이터 권한 기본값
    공유 데이터 권한(Shared data permissions) 게시자(publisher)의 자격 증명 없음(워크스페이스·계정 등록만 필요) 예
    개별 데이터 권한(Individual data permissions) 뷰어 각자의 자격 증명 기반 데이터에 대한 명시적 접근 권한 아니오

    공식 게시 문서는 공유 데이터 권한이 기본값이라고 설명합니다. 즉 게시 설정을 바꾸지 않으면 뷰어는 게시자의 권한으로 데이터를 봅니다.

    주의 공유 데이터 권한에서는 뷰어가 직접 권한을 받지 않은 데이터도 보일 수 있습니다. 공식 문서는 "This might expose data to users who have not been granted direct access to it."라고 명시합니다. 민감한 데이터를 담은 대시보드는 게시 전에 이 조건을 반드시 확인하십시오.

    1. 왜 필요한가¶

    이전 방식의 한계¶

    BI 도구에서 대시보드를 공유하는 전통적인 방식은 두 가지 극단 중 하나였습니다.

    • 각자 로그인: 뷰어마다 데이터 권한을 따로 주어야 합니다. 권한 관리 부담이 큽니다.
    • 공용 계정: 한 계정을 모두 씁니다. 누가 무엇을 봤는지 추적하기 어렵고, 최소 권한 원칙을 지키기 어렵습니다.

    AI/BI는 두 방식을 게시 설정으로 나눕니다. 넓게 공유하고 싶은 대시보드는 공유 데이터 권한으로, 행과 열 단위까지 사람마다 달라야 하는 대시보드는 개별 데이터 권한으로 게시합니다. 실제 데이터 접근 통제는 Unity Catalog 권한과 행 필터·열 마스크(06장)가 담당합니다.

    2. 어떻게 동작하는가¶

    초안과 게시본¶

    • 초안 은 작성자와 권한이 있는 사용자만 봅니다. 문서는 초안을 보는 뷰어에게는 게시 설정과 무관하게 각자의 권한이 적용된다 고 설명합니다.
    • 게시본 은 게시 시점의 스냅샷입니다. 초안을 고쳐도 게시본은 바뀌지 않습니다. 문서는 "The published version remains unchanged until you publish again."이라고 명시합니다.

    이 구조 때문에 작성자는 초안에서 실험하고, 검토가 끝나면 다시 게시해야 뷰어에게 변경이 반영됩니다.

    공유 데이터 권한의 동작¶

    공식 문서가 설명하는 흐름은 다음과 같습니다.

    1. 게시자가 공유 데이터 권한 으로 게시합니다.
    2. 뷰어가 게시본을 열면 쿼리가 게시자의 데이터 권한 으로 실행됩니다.
    3. 뷰어는 기반 데이터에 직접 권한이 없어도 결과를 봅니다.
    4. 뷰어는 워크스페이스나 계정에 등록되어 있어야 합니다.

    공유 데이터 권한의 캐시는 공유 캐시를 씁니다. 문서는 이 게시본의 예약 실행 결과도 같은 캐시를 채운다고 설명합니다.

    개별 데이터 권한의 동작¶

    1. 게시자가 개별 데이터 권한 으로 게시합니다.
    2. 뷰어가 게시본을 열면 쿼리가 뷰어 각자의 자격 증명 으로 실행됩니다.
    3. 뷰어는 기반 데이터에 명시적으로 접근할 수 있어야 결과를 봅니다.
    4. 컴퓨트 접근은 여전히 게시자의 자격 증명 으로 부여된다고 문서에 나옵니다.

    문서는 "Viewers run queries using their own credentials."와 "Compute access is always granted by the publisher's credentials."를 함께 명시합니다. 즉 데이터 권한은 뷰어의 것을 쓰지만, 쿼리를 돌릴 컴퓨트는 게시자가 제공합니다.

    참고 개별 데이터 권한에서 쿼리를 돌리는 컴퓨트를 뷰어가 따로 가질 필요는 없습니다. 다만 뷰어가 기반 데이터에 권한이 없으면 결과가 보이지 않습니다.

    두 방식 비교¶

    항목 공유 데이터 권한 개별 데이터 권한
    쿼리 실행 권한 게시자 뷰어
    뷰어의 데이터 권한 필요 여부 불필요 필요
    뷰어별 행 필터·열 마스크 적용 게시자 기준으로만 적용됨 뷰어 기준으로 적용됨
    캐시 공유 캐시 뷰어별 캐시 가능(새로고침 전용 예약 허용)
    외부 사용자(임베딩) 권장 비권장 권장

    주의 행 필터와 열 마스크는 UC의 권한 기준으로 평가됩니다. 공유 데이터 권한으로 게시하면 평가 기준이 게시자가 됩니다. 뷰어마다 다른 행을 봐야 하는 대시보드라면 개별 데이터 권한을 쓰십시오. 행 필터 설계는 06장 행 필터와 열 마스크를 참고하십시오.

    3. 어떻게 쓰는가¶

    게시 절차¶

    게시 버튼의 정확한 클릭 순서와 데이터 권한 선택 화면은 공식 문서의 "Publish a dashboard" 항목에서 확인하십시오. 이 장은 UI 순서를 추측으로 쓰지 않습니다. 확인된 개념은 다음과 같습니다.

    • 게시할 때 데이터 권한 방식(공유 또는 개별)을 정합니다.
    • 공유는 Share 대화 상자에서 사용자와 그룹 단위로 정합니다.
    • 공유 설정의 선택지는 "Only people with access can view"와 "Anyone in my account can view"입니다. 계정 전체 공유는 계정 사용자 등록이 필요합니다.

    참고 게시 방식을 고른 뒤에는 뷰어 역할로 게시본을 열어 실제로 데이터가 보이는지 확인하십시오. 공유 데이터 권한에서 권한이 없는 뷰어가 결과를 보는 것이 의도된 동작인지 이때 점검합니다.

    사용자 유형과 접근¶

    사용자 유형 접근 방식 제한
    워크스페이스 사용자 대시보드 권한(CAN RUN, CAN EDIT, CAN MANAGE)을 직접 부여 권한 수준에 따라 작성·게시 가능 여부가 다름
    워크스페이스 접근이 없는 사용자 CAN RUN만 가능 초안은 볼 수 없음
    계정 사용자(Account user) 관리자가 계정에 등록. 공유 데이터 권한 게시본을 봄 워크스페이스에 묶인(workspace-bound) 카탈로그의 데이터는 표시되지 않음
    Consumer access 엔타이틀먼트 보유자 공유된 대시보드·Genie Agent·Databricks Apps를 보고 대화 새 객체를 만들 수 없음

    공식 문서는 "Dashboard widgets that query workspace-bound securables do not display data for account users."라고 명시합니다. 계정 사용자에게 보여줄 대시보드는 워크스페이스에 묶이지 않은 데이터를 써야 합니다.

    대시보드 권한 수준¶

    문서는 대시보드 권한을 CAN RUN, CAN EDIT, CAN MANAGE 로 설명합니다. 소유권을 옮기면 새 소유자가 CAN MANAGE를 받습니다.

    소유권 이전 절차¶

    워크스페이스 관리자는 대시보드 소유자를 다른 사용자나 서비스 프린시펄로 바꿀 수 있습니다. 공식 관리 가이드의 절차는 다음과 같습니다.

    1. 대시보드를 열고 Share 를 누릅니다.
    2. Sharing 대화 상자에서 톱니바퀴 아이콘을 누릅니다.
    3. 새 소유자를 검색해 선택합니다.
    4. Confirm 을 누릅니다.

    게시본의 페이지 숨기기¶

    2026-08-27 릴리즈 노트에 따르면 작성자는 게시본에서만 페이지를 숨기고, 작성자에게는 그 페이지를 계속 보이게 할 수 있습니다. 라벨은 없습니다. 게시본 공개 범위를 좁힐 때 유용합니다.

    비공개 북마크¶

    2026-10-22 릴리즈 노트는 비공개 북마크(Private bookmarks)를 소개합니다. 뷰어는 필터 조합을 저장할 수 있고, 저장한 북마크는 본인에게만 보입니다. 라벨은 없습니다.

    서비스 프린시펄로 게시¶

    공식 문서는 서비스 프린시펄을 써서 대시보드를 게시하고 공유하는 방법을 별도 튜토리얼(API 기반)로 안내합니다. 이 장은 API 세부 사항을 다루지 않습니다. 자동화 방식은 11장에서 다룹니다.

    4. 트레이드오프¶

    공유 vs 개별 선택 기준¶

    상황 권장 방식 이유
    사내 전체가 같은 KPI를 본다 공유 데이터 권한 뷰어에게 권한을 나누어 줄 필요가 없음
    지역이나 부서마다 다른 행을 봐야 한다 개별 데이터 권한 행 필터가 뷰어 기준으로 평가되어야 함
    외부 사용자가 임베드된 화면으로 본다 개별 데이터 권한 공식 임베딩 문서가 외부 사용자에게 개별 권한을 권장
    민감 데이터를 넓게 보여줄 수 없다 개별 데이터 권한 공유 권한은 게시자 권한으로 데이터가 노출될 수 있음

    비용과 캐시¶

    • 공유 데이터 권한은 캐시를 공유하므로 같은 데이터를 여러 뷰어가 봐도 쿼리가 줄어드는 경향이 있습니다.
    • 개별 데이터 권한은 뷰어별 캐시가 가능하지만, 뷰어 수만큼 쿼리가 늘어날 수 있습니다.
    • 캐시 세부 동작은 4페이지 예약·구독과 임베딩에서 다룹니다.

    5. 주의사항¶

    • 기본값을 그대로 쓰지 않습니다. 게시 설정의 기본값은 공유 데이터 권한입니다. 데이터 민감도를 확인한 뒤 의도적으로 고르십시오.
    • 행 필터와 열 마스크를 설계합니다. 공유 권한에서는 행 필터가 게시자 기준으로 평가됩니다. 뷰어마다 다른 행이 필요하면 개별 권한을 쓰십시오.
    • 계정 사용자와 워크스페이스 카탈로그를 구분합니다. 워크스페이스에 묶인 데이터는 계정 사용자 화면에 나오지 않습니다.
    • 게시 후 수정은 다시 게시해야 반영됩니다. 초안 수정이 바로 뷰어에게 보이지 않는다는 점을 작성 팀에 알리십시오.
    • 소유자가 퇴사하면 소유권을 옮깁니다. 소유권 이전 절차를 운영 절차에 넣으십시오.
    • 임베딩 대시보드는 게시본이어야 합니다. 초안은 임베드할 수 없습니다. 4페이지를 참고하십시오.
