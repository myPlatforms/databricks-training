    대시보드 작성: 데이터셋·위젯·필터·파라미터¶

    기준일: 2026-10-28 · 근거: 공식 문서 · 수준: 200

    한눈에 보기¶

    AI/BI 대시보드는 데이터셋(Dataset)에서 데이터를 읽고, 그 결과를 위젯(Widget)으로 그리는 구조입니다. 사용자는 필터(Filter)와 파라미터(Parameter)로 같은 데이터에서 원하는 범위를 고릅니다. 한 대시보드는 여러 페이지(Page)로 구성할 수 있습니다.

    흐름은 데이터셋에서 시작해 위젯, 페이지, 대시보드 순으로 쌓이며, 필터와 파라미터는 뷰어가 조작하는 입력입니다. 구성 요소는 아래 표로 정리합니다.

    개념 역할 주요 설정 위치
    데이터셋(Dataset) 쿼리 결과를 담는 단위. 여러 위젯이 같은 데이터셋을 공유 Data 탭
    위젯(Widget) 시각화, 필터, 텍스트 상자, 이미지 캔버스
    필터(Filter) 뷰어가 값을 고르는 컨트롤. 필드 필터와 파라미터 필터로 나뉨 캔버스 또는 필터 위젯
    파라미터(Parameter) 쿼리 본문에 :이름 형태로 들어가 실행 시점에 값을 대입 데이터셋 쿼리 + 필터 위젯 연결
    페이지(Page) 위젯을 묶는 화면 단위. 페이지마다 필터 범위를 둘 수 있음 페이지 탭

    이 장은 UI에서의 작성을 기준으로 씁니다. 대시보드를 코드로 관리하는 방법(Declarative Automation Bundles, REST API, Git 연동)은 11장에서 다룹니다.

    1. 왜 필요한가¶

    이전 방식의 한계¶

    • 같은 데이터를 여러 차트가 쓸 때 차트마다 쿼리를 따로 실행하면 같은 값이 다르게 보일 수 있고, 쿼리 비용도 중복됩니다.
    • 필터를 바꿀 때마다 쿼리를 고치는 방식은 현업 사용자에게 적합하지 않습니다.
    • 대시보드 하나에 모든 질문을 넣으면 로딩이 느려지고 화면이 복잡해집니다.

    AI/BI 대시보드는 데이터셋을 공유 단위로 만들고, 필터와 파라미터를 뷰어 쪽 조작으로 분리해 이 문제를 줄입니다.

    2. 어떻게 동작하는가¶

    데이터셋의 종류¶

    공식 문서가 설명하는 데이터셋 소스는 다음과 같습니다.

    소스 설명 주의
    Unity Catalog 테이블·뷰 기본 쿼리는 SELECT *이며 수정할 수 있음 테이블 이름은 3단계로 지정
    SQL 쿼리 사용 가능한 데이터 소스에서 쿼리를 작성 쿼리 안의 정규화된 이름이 카탈로그·스키마 선택기보다 우선
    업로드 파일 파일로부터 UC 테이블을 생성 덮어쓰기에는 해당 스키마의 MANAGE 권한이 필요
    로컬 메트릭 뷰 시각 인터페이스에서 정의하며 대시보드 범위에 머묾. UC에는 게시하지 않음 2026-08-20 릴리즈 노트에서 GA
    메트릭 뷰 쿼리 SQL에서 뷰처럼 참조하며, 측정값은 MEASURE() 함수로 접근 7페이지 참고

    메트릭 뷰를 데이터셋으로 쓸 때, 메트릭 뷰 데이터셋에는 정의된 차원과 측정값이 모두 포함됩니다. 문서는 이 데이터셋에서 쿼리를 편집해 열을 빼거나 필터를 추가할 수 없다고 명시합니다.

    위젯과 캔버스¶

    위젯은 시각화, 필터, 텍스트 상자, 이미지로 나뉩니다. 공식 문서 기준으로 위젯 하나는 데이터셋의 결과를 받아 그립니다. 시각화 종류는 막대, 선, 영역, 산점도, 원형, 히트맵, 피벗 테이블 등 여러 가지입니다.

    텍스트 위젯과 위젯 제목에는 리치 텍스트를 쓸 수 있습니다. 2026-08-06 릴리즈 노트에 따르면 제목과 설명에 서식, 링크, 표를 넣을 수 있습니다. 2026-09-17 릴리즈 노트에는 제목이나 설명에 @를 입력하면 살아 있는(live) 서식 지정 지표 참조를 넣을 수 있다는 항목도 있습니다.

    필터의 종류와 범위¶

    공식 필터 문서가 설명하는 필터 유형은 다음과 같습니다.

    구분 유형
    필드 필터(Field filter) 단일 값, 다중 값, 날짜 선택기, 날짜 범위 선택기, 텍스트 입력, 범위 슬라이더
    파라미터 필터(Parameter filter) 단일 값, 다중 값, 날짜 선택기, 날짜 범위
    쿼리 기반 파라미터 필드 필터와 파라미터 필터를 한 위젯에 합친 형태

    필터의 적용 범위는 세 단계입니다.

    범위 설정 방법 적용 대상
    글로벌 필터(Global filter) 왼쪽 위 필터 아이콘 → + 같은 데이터셋을 쓰는 시각화 전체(페이지를 가로질러)
    페이지 필터(Page filter) 페이지에 필터 위젯을 배치 같은 페이지에서 같은 데이터셋을 쓰는 시각화
    위젯 필터(Widget-level filter) 작성자가 정한 고정 값 해당 위젯에만 적용. 뷰어는 바꿀 수 없음

    활성 필터 바(Active filter bar)에는 "All"이 아닌 글로벌 필터, 페이지 필터, 교차 필터가 표시됩니다.

    관계 범위 필터(Relationship-scoped filtering)¶

    대시보드 관계(dashboard relationships)로 정의한 의미 모델을 쓰면, 선택 값이 조인 그래프를 따라 관련 데이터셋으로 흐릅니다. 2026-09-10 릴리즈 노트는 "Relationship-scoped filters"를 Public Preview로, 2026-09-03 릴리즈 노트는 "Cross-dataset filtering through relationships"를 Public Preview로 표기합니다. 두 항목은 이름이 달라 같은 기능인지 확인이 필요합니다. 릴리즈 노트의 설명은 "각 위젯은 자신과 관련된 데이터셋의 필터에만 반응한다"와 "한 데이터셋의 필터가 관련 데이터셋 위젯으로 넘어간다"입니다.

    주의 관계 범위 필터는 Public Preview입니다. 운영 대시보드에 의존하기 전에 대상 워크스페이스에서 동작을 확인하십시오.

    위젯별 필터 무시¶

    위젯 설정 패널의 Ignored filters 에서 특정 위젯이 일부 필터를 무시하도록 지정할 수 있습니다. 선택지는 Global filters 와 Page filters(Filter와 Visualization으로 나뉨)이며, All 을 고르면 한 단계 전체를 무시합니다.

    이 설정은 필터와 교차 필터에만 적용되고 파라미터에는 적용되지 않습니다. 드릴 스루(drill-through)는 여전히 위젯에 영향을 줍니다. 2026-09-24 릴리즈 노트에 따르면 이 기능은 위젯이 일부 필터를 무시하는 동안 나머지 페이지에는 필터가 계속 적용되는 방식입니다.

    파라미터¶

    파라미터는 쿼리 본문에 :키워드 형태로 넣고, 필터 위젯을 연결해 뷰어가 값을 바꾸게 합니다. 공식 문서 예시는 메트릭 뷰의 명명된 인자(named argument)에 파라미터를 넘기는 형태입니다.

    SELECT
  MEASURE(`Discounted Sales`),
  MEASURE(`Total Sales`)
FROM catalog.schema.metric_view(discount => :discount)

    위 예시에서 :discount는 대시보드에 노출된 필터 위젯의 값으로 치환되고, 쿼리는 값이 바뀔 때마다 다시 실행됩니다. 노출하지 않은 파라미터는 Data 탭에서 설정한 기본값을 씁니다.

    파라미터의 특징은 다음과 같습니다.

    • 실행 시점에 값을 대입하므로 항상 쿼리를 다시 실행 합니다.
    • 쿼리 안 어디에든 둘 수 있습니다. 조인 앞이나 서브쿼리 안도 가능합니다.
    • 필드 필터는 작은 데이터셋에서 브라우저 안에서 처리되므로 대개 더 빠릅니다.

    참고 문서는 파라미터의 데이터 타입을 명시하지 않습니다. 파라미터 타입을 쓰기 전에 대상 기능 페이지에서 확인하십시오.

    데이터셋 구체화(Materialization)¶

    데이터셋을 Export to Materialized View 로 구체화된 뷰(materialized view)로 내보낼 수 있습니다. 구체화된 뷰는 결과를 캐시하고 일정에 따라 갱신합니다. 기본적으로 대시보드에 함께 추가되며, 끌 수 있습니다.

    상태 라벨에는 주의가 필요합니다. 데이터셋 구체화 문서 페이지에는 Beta 라벨이 없지만, 2026-10-01 릴리즈 노트는 "Materialize SQL datasets"를 Beta로 표기합니다. 같은 문서의 메트릭 뷰 내보내기는 Public Preview로 표기되어 있습니다. 세 표기가 엇갈리므로 이 장에서는 릴리즈 노트의 Beta를 기준으로 쓰고, 실제 적용 전에 대상 워크스페이스에서 확인하십시오.

    주요 한도¶

    공식 문서 "Dashboard limits"에서 확인한 수치는 다음과 같습니다.

    항목 한도
    대시보드당 페이지 15
    대시보드당 데이터셋 100
    페이지당 위젯(시각화·필터·텍스트·이미지 포함) 100
    드롭다운·다중 선택 필터의 고유 값 표시 100,000
    다중 선택 필터에 한 번에 붙여넣기 1,000 값
    대부분의 시각화(막대·선·영역·산점도·원형·히트맵 등) 렌더링 행 수 15,000
    테이블 시각화 렌더링 행 수 100,000
    작은 데이터셋 기준(브라우저에서 처리) 100,000행 또는 100 MB 이하

    데이터셋 크기 자체에는 하드 리밋이 없다고 문서에 명시되어 있습니다. 100,000행 또는 100 MB를 넘는 데이터셋은 쿼리를 WITH 절로 감싸 백엔드에서 시각화 쿼리를 실행합니다.

    3. 어떻게 쓰는가¶

    작성 순서¶

    1. 데이터 소스를 정합니다. 가능하면 UC의 테이블이나 메트릭 뷰를 씁니다.
    2. Data 탭에서 데이터셋을 만듭니다. 필요한 열만 고르고, 파라미터는 :이름으로 넣습니다.
    3. 캔버스에 시각화를 놓고 데이터셋을 연결합니다.
    4. 필터 위젯을 추가하고, 파라미터에 연결하거나 필드 필터로 설정합니다.
    5. 글로벌 필터와 페이지 필터의 범위를 정합니다.
    6. 위젯마다 필요한 경우에만 Ignored filters 를 설정합니다.
    7. 대시보드를 게시하기 전에 3페이지의 자격 증명 모델을 확인합니다.

    예시: 메트릭 뷰를 파라미터와 함께 쓰는 데이터셋¶

    데이터셋 쿼리에 아래 형태를 씁니다.

    SELECT
  MEASURE(`Discounted Sales`),
  MEASURE(`Total Sales`)
FROM catalog.schema.metric_view(discount => :discount)

    그다음 캔버스에 단일 값 필터를 추가하고 discount 파라미터에 연결합니다. 뷰어가 값을 바꾸면 대시보드가 :discount를 그 값으로 치환해 쿼리를 다시 실행합니다.

    4. 트레이드오프¶

    • 데이터셋을 공유하면 쿼리 수가 줄지만, 데이터셋이 크면 모든 위젯이 그 비용을 함께 나눠 냅니다. 필요한 열만 고르고, 큰 데이터셋은 구체화나 필터 설계를 함께 검토하십시오.
    • 필드 필터는 빠르지만 작은 데이터셋에 맞습니다. 큰 데이터셋에서는 파라미터 방식이 더 안정적입니다. 파라미터는 값이 바뀔 때마다 쿼리를 다시 실행합니다.
    • 글로벌 필터는 편하지만 범위가 넓습니다. 같은 데이터셋을 쓰는 모든 위젯에 영향을 주므로, 일부 위젯만 다른 값을 봐야 하면 Ignored filters 를 쓰는 편이 안전합니다.
    • 관계 범위 필터는 연결이 깔끔하지만 Public Preview입니다. 운영 용도라면 데이터셋 설계를 단순하게 두고 필터를 페이지 단위로 제한하는 편이 낫습니다.

    언제 쓰지 않는가¶

    • 데이터셋 하나가 수백만 행을 가지고 모든 필터가 실시간 값을 요구하는 경우에는 대시보드보다 사전 집계(구체화된 뷰)와 별도 화면을 먼저 검토하십시오.
    • 한 대시보드에 100개를 넘는 위젯이 필요하면 페이지를 나누거나 대시보드를 분리해야 합니다.

    5. 주의사항¶

    • 데이터셋의 열 이름과 정의를 메타데이터로 관리합니다. 열 이름이 현업 용어와 다르면 Genie Agent에서도 질문이 어긋납니다. 6페이지의 메타데이터 설계와 같은 원칙입니다.
    • 메트릭 뷰 데이터셋은 편집하지 않습니다. 메트릭 뷰 데이터셋의 쿼리는 열을 빼거나 필터를 더할 수 없습니다. 필터가 필요하면 파라미터나 필터 위젯으로 처리합니다.
    • 파라미터 이름을 충돌 없이 짓습니다. 같은 이름의 파라미터가 여러 데이터셋에 있으면 필터 한 개가 여러 데이터셋에 같이 영향을 줄 수 있습니다.
    • 쿼리 안의 정규화된 이름은 선택기보다 우선합니다. 카탈로그 선택기를 바꿔도 쿼리에 catalog.schema.table이 박혀 있으면 그 이름을 씁니다.
    • 업로드 파일 데이터셋은 덮어쓰기 권한을 확인합니다. 기존 테이블을 덮어쓰려면 해당 스키마에 MANAGE가 필요합니다.
    • 대시보드 한도를 설계 단계에서 확인합니다. 페이지 15개, 데이터셋 100개, 위젯 100개는 대규모 대시보드에서 먼저 닿는 한계입니다.
    • 구체화 기능의 라벨을 확인합니다. 릴리즈 노트의 Beta와 문서 페이지의 표기가 다를 수 있습니다.

    참고 대시보드의 작성과 게시 흐름을 코드로 관리하는 방법은 11장에서 다룹니다.
