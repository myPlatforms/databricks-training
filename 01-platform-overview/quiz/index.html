    퀴즈와 체크리스트¶

    기준일: 2026-10-29 · 근거: 이 장 본문 · 수준: 100~300

    이 장에서 다룬 내용을 확인하는 문제입니다. 정답을 펼치면 해설과 근거 페이지로 가는 링크가 있습니다.

    퀴즈¶

    1. Databricks에서 "관리형(managed)"이 뜻하는 것으로 알맞은 것은? (수준 100)¶

    • A. 모든 데이터를 Databricks 계정 안에만 저장한다
    • B. 클러스터 기동, 런타임 업그레이드, 메타데이터 관리 같은 운영 작업의 상당 부분을 플랫폼이 맡는다
    • C. 사용자가 Spark 코드를 직접 컴파일해서 배포해야 한다
    • D. 데이터 웨어하우스 엔진 하나만 사용한다
    정답과 해설

    정답: B — 이 장이 옮긴 공식 소개 내용에서 관리형은 운영 작업의 상당 부분을 플랫폼이 맡는다는 뜻입니다. 데이터는 고객의 클라우드 저장소에 남으므로 A는 틀립니다. C와 D는 본문에 없는 내용입니다.

    근거: 플랫폼이란 무엇인가 — 한눈에 보기

    2. 워크스페이스 UI와 제어 로직이 동작하는 control plane은 어디에 있는가? (수준 100)¶

    • A. 고객의 클라우드 계정 안, 워크스페이스의 가상 네트워크
    • B. Databricks 계정 안 (고객 클라우드 계정 밖)
    • C. 서버리스 컴퓨트를 쓸 때만 고객 클라우드 계정 안
    • D. 메타스토어가 있는 리전의 스토리지 버킷
    정답과 해설

    정답: B — 아키텍처 페이지는 control plane을 "Databricks 계정 안, 고객 클라우드 계정 밖"에 있다고 설명하며, 웹 애플리케이션(UI)도 여기서 동작한다고 적습니다. A는 클래식 컴퓨트 플레인의 위치이고, C는 서버리스 컴퓨트 플레인을 잘못 옮긴 것입니다(서버리스 컴퓨트도 Databricks 계정 안에 있습니다). D는 스토리지 위치와 섞은 보기입니다.

    근거: 플랫폼 아키텍처 — 한눈에 보기

    3. 계정(account), 워크스페이스(workspace), 메타스토어(metastore) 중 청구와 지원이 계정 단위로 처리되는 것은? (수준 100)¶

    • A. 워크스페이스
    • B. 노트북
    • C. 계정
    • D. 카탈로그
    정답과 해설

    정답: C — 계정은 청구와 지원이 처리되는 단위이며 워크스페이스를 묶는 최상위 단위입니다. 워크스페이스는 팀이 작업하는 공간이고, 메타스토어는 카탈로그·스키마·테이블의 메타데이터와 권한을 등록하는 계정 수준 구성 요소입니다. 노트북과 카탈로그는 이 계층 구분의 대상이 아닙니다.

    근거: 계정·워크스페이스·메타스토어 — 2. 계정: 청구와 관리의 단위

    4. 노트북에서 Python 셀로 만든 변수를 SQL 셀에서 바로 쓸 수 있는가? (수준 200)¶

    • A. 가능하다. 같은 노트북 안에서는 변수가 자동으로 공유된다
    • B. 불가능하다. 언어마다 실행 환경(REPL)이 분리되어 있어 임시 뷰나 테이블을 거쳐야 한다
    • C. 가능하다. %run으로 호출하면 변수가 공유된다
    • D. 불가능하다. 노트북 하나에는 한 언어만 쓸 수 있다
    정답과 해설

    정답: B — 공식 문서는 언어마다 변수와 상태가 분리된다고 명시합니다. 언어 사이에서 값을 넘길 때는 임시 뷰나 테이블 같은 외부 자원을 거칩니다. 노트북은 셀마다 언어를 바꿀 수 있으므로 D도 틀립니다.

    근거: 노트북 기초 — 2. 지원 언어

    5. %run을 사용할 때 맞는 설명은? (수준 200)¶

    • A. 다른 명령과 같은 셀에 섞어 써도 된다
    • B. 셀 안에 단독으로 있어야 한다
    • C. 함수는 가져오지만 변수는 가져오지 않는다
    • D. 어떤 컴퓨트에서든 위젯 값을 넘길 수 있다
    정답과 해설

    정답: B — %run은 노트북 전체를 인라인으로 실행하므로 셀 안에 단독으로 있어야 한다고 공식 문서가 설명합니다. 범위는 노트북 전체이므로 함수와 변수가 모두 들어옵니다(C 틀림). 위젯 값을 넘기는 형식은 클러스터에 연결된 노트북 기준이라고 본문에 적혀 있으므로 D도 틀립니다.

    근거: 노트북 기초 — 5. %run: 다른 노트북 불러오기

    6. SQL 셀에서 위젯 값 database와 table을 받아 테이블 이름으로 쓰려면 어떻게 해야 하는가? (수준 200)¶

    • A. FROM :table로 쓴다
    • B. FROM IDENTIFIER(:database || '.' || :table)로 쓴다
    • C. FROM '${table}'로 쓴다
    • D. FROM table(:table)로 쓴다
    정답과 해설

    정답: B — 파라미터 마커(:name)는 값을 넣는 데 쓰고, 객체 이름은 IDENTIFIER()로 감싸야 합니다. :table을 직접 쓰면 값으로 처리되어 실패합니다. A는 이 주의사항에 정면으로 어긋나고, C와 D는 본문에 없는 문법입니다.

    근거: 노트북 기초 — SQL에서 위젯 값 쓰기

    7. system.billing.usage로 DBU 합계를 낼 때 가장 주의할 점은? (수준 200)¶

    • A. record_type은 무시해도 항상 정확하다
    • B. usage_unit과 usage_quantity를 무시하고 레코드 행 수를 센다
    • C. record_type을 고려하지 않으면 정정 레코드(RETRACTION, RESTATEMENT)가 합계에 섞일 수 있다
    • D. 레코드가 실시간으로 반영되므로 지연을 고려할 필요가 없다
    정답과 해설

    정답: C — 본문은 RETRACTION이 원래 레코드를 상쇄하고 RESTATEMENT가 정정 값을 담는다고 설명하며, record_type을 고려하지 않으면 합계가 틀어질 수 있다고 주의합니다. 사용량 레코드는 지연되어 나타나므로 D는 틀립니다.

    근거: 과금 모델 기초 — 3. 사용량 조회 systembillingusage

    8. 기본 스토리지(Default storage)에 있는 데이터 자산을 다루는 방법으로 맞는 것은? (수준 300)¶

    • A. 클래식 컴퓨트에서도 문제없이 직접 읽고 쓸 수 있다
    • B. 클래식 컴퓨트는 직접 다룰 수 없으므로 데이터 위치를 먼저 확인해야 한다
    • C. 기본 스토리지에 있으면 서버리스 컴퓨트와 클래식 컴퓨트에서 같은 방식으로 쓸 수 있다
    • D. 기본 스토리지는 클래식 워크스페이스에서만 만들어진다
    정답과 해설

    정답: B — 공식 문서는 클래식 컴퓨트(서버리스가 아닌 모든 컴퓨트)가 기본 스토리지의 데이터 자산과 상호작용할 수 없다고 명시합니다. 서버리스 워크스페이스가 기본 스토리지를 쓰므로 D는 틀리고, 클래식 컴퓨트 제약이라는 점에서 A도 틀립니다.

    근거: 플랫폼 아키텍처 — 기본 스토리지(Default storage)의 제약

    9. 같은 리전의 워크스페이스 여러 개가 데이터 권한을 한 곳에서 관리하려면 어떤 구조가 맞는가? (수준 300)¶

    • A. 워크스페이스마다 별도 메타스토어를 만들어 데이터를 복제한다
    • B. 메타스토어 없이 DBFS 루트를 공유한다
    • C. 같은 리전의 워크스페이스가 하나의 메타스토어를 공유한다
    • D. 리전이 달라도 한 메타스토어에 묶어 관리한다
    정답과 해설

    정답: C — 메타스토어는 계정 수준에 있으며, 같은 리전의 여러 워크스페이스가 공유할 수 있습니다. A는 권한 체계를 쪼개고 데이터를 복제하는 설계이고, B는 본문이 권장하지 않는 DBFS 루트 방식입니다. D는 메타스토어를 리전 단위로 생각해야 한다는 주의사항과 어긋납니다.

    근거: 계정·워크스페이스·메타스토어 — 1. 계층 관계, 계정·워크스페이스·메타스토어 — 8. 주의사항

    실무 체크리스트¶

    이 장의 내용을 실제 환경에 적용할 때 확인할 항목입니다.

    • 클래식 컴퓨트를 쓸 계획이면 대상 데이터가 기본 스토리지에 있는지 먼저 확인한다 — 플랫폼 아키텍처
    • 클래식 워크스페이스의 스토리지 버킷을 삭제하거나 수정하지 않는다 — 플랫폼 아키텍처
    • 여러 워크스페이스가 같은 데이터를 보려면 같은 리전인지 확인하고 메타스토어를 공유하도록 설계한다 — 계정·워크스페이스·메타스토어
    • 노트북을 실행하기 전에 런타임 버전과 컴퓨트 종류(서버리스 또는 클래식)를 확인한다 — 노트북 기초
    • 노트북 안에 토큰이나 비밀번호를 직접 쓰지 않고 별도 비밀 저장소를 쓴다 — 노트북 기초
    • 비용은 system.billing.usage로 확인하되 record_type과 기록 지연을 함께 고려한다 — 과금 모델 기초
    • 무료 체험을 마치기 전에 컴퓨트를 종료하고 결제 정보 설정을 확인한다 — 시작하기
    • 메뉴 이름과 위치는 화면 버전에 따라 바뀌므로, 문서를 옮길 때 기준일과 워크스페이스 버전을 함께 적는다 — 워크스페이스 UI
